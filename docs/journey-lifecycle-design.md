# 펫무브 여정 생애주기(Lifecycle) 설계

> 여정의 **완료 · 지난 여정 · 완료 확인 · 관련성 · 표식** 단일 출처. 작성 2026-06-08.

## 0. 한눈에 (요약)

한 케이스 = 한 동물 = **N개의 목적지(여정)**. 각 여정은 한 번의 출국 건.

1. **데이터는 두 층** — 동물에 붙는 사실(접종·검사: 모든 여정 공유) vs 여정에 붙는 절차(출국일·검역 등: 목적지별 분리). 기존 구조 유지.
2. **같은 목적지 "동시" 2개는 금지** (극히 드묾) → 현재 진행 중 여정은 항상 **목적지 이름으로 유일**하게 구분. 그래서 무거운 여정 ID 전환이 **불필요**(§2.2).
3. **지난 여정은 풀 보관 안 함** → 완료 시 **요약 한 줄**(`past_journeys`: 목적지·기간·도장)만 남겨 "지난 여정 카드"로. 발급 서류·동물 의료이력은 이미 영구 보존.
4. **완료** = 도착 자동(`has-arrived`) / **보호자 확인 prompt**(A·B) / 스태프 수동 전환.
5. **첫 화면** = 진행 중 여정(들) 우선, 없으면 가장 최근 완료 여정 1개.
6. **표식은 출국일 기준** — 진행 중은 목적지명으로 구분(표식 거의 불필요), 지난 여정 카드는 출국 년월일 + 도착 도장.

## 1. 배경·결정

지금까지 운영(펫무브워크): 여정이 끝나면 그대로 두고, 새 목적지가 생기면 **이전 목적지를 삭제**. 그래서 "지난 여정"이 보존되지 않았다.

바꾸는 것 + 그 과정의 핵심 결정(2026-06-08):
- 끝난 여정을 삭제하지 않고 **"지난 여정"으로 요약 보존**.
- **여정 ID 전환은 미채택** — 조사 결과 100곳+·수 주·프로덕션 마이그레이션이라 위험·비용이 큰데, 그 유일한 이유(같은 목적지 2개)가 드물고, "지난 여정 풀 타임라인"의 가치는 낮음(서류 PDF + 동물 의료이력이 이미 커버). → **요약 모델 + 동시 같은 목적지 금지**로 같은 가치를 훨씬 가볍게 달성.

> ⚠️ **과거 데이터 주의:** 기존에 삭제 방식으로 지운 옛 여정은 **복구 불가**. "지난 여정"은 **이번 변경 이후 완료되는 여정부터** 요약으로 쌓인다.

## 2. 데이터 모델

### 2.1 두 층 — 동물 단위 vs 여정 단위 (기존, 양쪽 대칭) + 지난 여정 요약

| 층 | 성격 | 저장 |
|---|---|---|
| **동물 단위** | 영구 사실, 모든 여정 공유 | `case.data` top-level 단일 (마이크로칩, `rabies_dates`, `rabies_titer_records`, 종합/CIV, 구충, 품종·생년월일, 보호자 신원) |
| **여정 단위** | 그 출국 한 건에만 의미 | `case.data.by_dest[목적지명]` (출국일·항공편·검역·증명서·해외주소·구충 시각) — [DESTINATION_SCOPED_FIELD_KEYS](../packages/domain/src/destination-scoped-fields.ts) |
| **지난 여정 요약** *(신설)* | 완료/취소된 여정의 한 줄 요약 | `case.data.past_journeys[]` = `{ destination, departureDate, returnDate?, tripType, status('done'\|'cancelled'), completedDate }` |

- 의료기록 수정(오타 정정)은 모든 여정에 반영되는 게 맞다 — 같은 동물의 같은 접종은 하나의 사실.
- `past_journeys`는 **카드용 요약만** — 풀 절차 타임라인은 안 남긴다. 발급 서류는 서류 탭(PDF), 의료이력은 동물 단위로 이미 영구.

### 2.2 같은 목적지 처리 — 여정 ID 없이

- **동시** 같은 목적지 2개(일본 6월 + 일본 10월 둘 다 진행 중)는 **금지** (극히 드묾). → 진행 중 여정은 `by_dest[목적지명]` 키로 충돌 없이 유일.
- **순차** 재방문(작년 일본 다녀옴 → 올해 또 일본)은 자연 해결: 작년 일본은 완료되며 `past_journeys` 요약으로 내려가고 `by_dest[일본]`은 비워짐 → 올해 일본이 새로 시작. (현재 진행은 늘 일본 1개.)
- 따라서 `by_dest`·`trip_type` 키를 여정 ID로 바꾸는 [전환](journey-id-migration.md)은 **하지 않는다.** (향후 같은 목적지 *동시* 진행이 정말 필요해지면 그때 재검토.)

## 3. 관련성 — 이 여정에 무엇을 보일까

의료기록 **사실은 동물 단위로 그대로**, "이 여정에 관련 있나"(관련성)만 목적지별로 저장(양쪽 공유). 세 소스:

| 소스 | 예시 | 누가 |
|---|---|---|
| **규칙 (기본)** | 일본→종합백신 안 뜸 / 베트남→광견병 최신 1건 / 중국→유효한 검사만 | 시스템 자동 |
| **＋ 수동 추가** | 일본 여정에 종합백신 카드 넣기 | 스태프 |
| **− 수동 제외** | 이 여정엔 불필요한 옛 기록 빼기 | 스태프 |

- 규칙 필터 재료(목적지별 적용 step, 유효기간)는 이미 도메인에 있음([applicability.ts](../packages/domain/src/journey-steps/applicability.ts), [procedure-checks/](../packages/domain/src/procedure-checks/)).

**삭제 2종** (결과는 양쪽 공유): "여정에서 빼기"(관련성 제거, 이력 보존) vs "사실 말소"(정정, 모든 여정 반영).

**권한**: 보호자 = 기록 입력·수정 + **완료/취소 확인**(§4)만. 추가·제외·말소·전환 = **스태프**.

## 4. 완료 + 완료 확인 prompt

### 4.1 완료가 되는 경로

| 경로 | 조건 |
|---|---|
| **자동** | 도착 판정 `has-arrived` — 왕복=한국 수입검역 확인, 편도=도착(일본 편도는 일본 수입검역) ([done-resolver.ts](../packages/domain/src/journey-steps/done-resolver.ts)) |
| **보호자 확인** | 아래 prompt 에서 "잘 다녀왔어요"/"취소" 선택 |
| **스태프 전환** | 펫무브워크에서 수동으로 완료/취소 처리 (고객이 검역 완료 미체크하고 다녀온 경우 등) |

완료되면 그 여정을 `past_journeys` 요약으로 남기고 `by_dest[목적지명]`을 비운다.

### 4.2 완료 확인 prompt (보호자)

완료 미확인 여정이 방치되는 걸 돕는 **부드러운 확인**. 그 여정(일정 탭) 진입 시 팝업.

**A형 — 완료 확인** (출국/귀국일 **다음날부터**)
> **{동물}와(과)의 {목적지} 여정 잘 마쳤나요?**
> ・ 잘 다녀왔어요 → 완료(도장) ・ 아직 진행 중이에요 → 닫기 ・ 이 여정은 취소할게요 → 취소

**B형 — 중단 확인** (출국일 없이 접종·항체 **유효기간 만료**, 한 달 전 갱신 안내 후에도 방치)
> **{동물}의 {목적지} 준비가 멈춰 있어요. 계속 준비하시나요?**
> ・ 네, 계속 준비할게요 → 유지(추가 검사 안내) ・ 이 여정은 취소할게요 → 취소

규칙:
- **재발동**: "진행 중/계속"으로 닫으면 — A형은 출국/귀국일이 **바뀌고 그 날짜가 지나면** 다시. B형은 **한 번만**(이후 방치는 스태프 정리).
- **위치**: 앱 진입이 아니라 **그 여정(일정 탭) 진입 시**.
- **권한**: 현재 펫무브 전부 무료라 **취소도 보호자 직접 OK**. 결제 도입 시 "취소 → 담당자 확인"으로 보강.
- **"와/과"** 는 동물 이름 받침에 따라 자동 (몽이**와** / 콩**과**).
- **강제 아님**: 안 눌러도 여정 안 망가짐 → 스태프가 정리(이중 안전망). 자동 삭제 ❌.
- 저장: 여정(목적지)별로 "언제·어느 날짜 기준으로 물었는지" 가벼운 표시만.

## 5. 지난 여정

- **요약 카드(도장)** — `past_journeys`를 렌더. 완료(`status:'done'`)는 도착 도장 + 목적지 + 기간(출국~귀국). 추억 상기 톤.
- **위치** — 펫무브: **내 정보 > 반려동물 > [동물] > 여정**, 진행 중 목적지 카드 **아래**에 지난 여정 카드. (일정 탭은 현재 진행 중심.)
- **취소**(`status:'cancelled'`)는 추억 카드와 안 어울림 → 조용히 정리(목록에서 빼거나 "취소됨" 흐리게).
- 카드를 눌렀을 때: 도장 + 목적지 + 기간 요약. (풀 절차는 데이터가 없어 못 보여줌 — 요약 모델의 자연스러운 결과. 발급 서류 다시보기 링크를 넣을지는 미해결 §10.)
- **완료 카드 + 지난 여정 카드는 도장 스타일로 통일 디자인** (portal-preview에서).

## 6. 첫 화면 규칙

> - **진행 중 여정이 있으면** → 그것(들)을 첫 화면에 (여러 개면 병렬)
> - **진행 중이 없으면** → 가장 최근(완료일 기준) 여정 1개
> - 나머지 완료 → "지난 여정"으로

| 케이스 상황 | 첫 화면 | 지난 여정 |
|---|---|---|
| 일본만 진행 중 | 일본 | — |
| 일본·베트남 둘 다 진행 중 | 일본 + 베트남 | — |
| 일본 완료, 다른 여정 없음 | 일본(완료 카드) | — |
| 일본 완료 + 베트남 진행 중 | 베트남 | 일본 |
| 일본·베트남 둘 다 완료 | 베트남(가장 최근) | 일본 |

## 7. 양쪽 앱 일관성

**동작(사실·판정)은 공유로 보장, 표시(화면)는 각 앱 톤.**

- **공유에 둘 것** — 관련성 판정, 추가/제외·완료·취소 상태, `past_journeys`. `case.data` + `packages/domain`에 두면 양쪽 자동 일치.
- **각 앱 톤** — 펫무브워크=스태프 입력 폼, 펫무브=보호자 카드/타임라인.
- **표시 정책 차이 허용** — 같은 판정이라도 펫무브는 관련 없는 옛 기록 숨김, 펫무브워크는 전체 + "유효/만료" 배지.
- 현재 비대칭: 펫무브엔 타임라인·완료 배너 있음(확장), 펫무브워크엔 journey 카탈로그·완료 상태 없음(`status` 컬럼 과거 삭제) → 관련성 필터·완료/지난 여정이 새로 들어감.

## 8. 표식 규칙

같은 목적지 동시 2개를 금지하므로 진행 중 표식은 단순:

| 상황 | 표식 |
|---|---|
| 진행 중 (목적지명으로 구분) | **한국 ⇄ 일본** (별도 표식 없음 — 왕복 화살표는 여행 이미지로 유지) |
| 지난 여정 카드 | **일본 · 2025.06.23** (출국 년월일) + 도착 도장 ✓ |
| 지난 여정 상세 | 2025.06.23 출국 ~ 2025.11.15 귀국 (왕복) |

- 날짜 표기는 `2025.06.23` 점 형식 기본 (한글 풀이 여부는 시안에서).
- (구버전의 "같은 목적지 2개 → 출국월·흐림" 표식은 동시 금지로 **폐기**. portal-preview timeline의 해당 데모도 제거 예정.)

## 9. 구현 단계 (대폭 가벼워짐 — 여정 ID 전환 없음)

> 디자인은 [docs/portal-preview/](portal-preview/) 시안을 먼저 고치고 코드에 반영([apps/portal/CLAUDE.md](../apps/portal/CLAUDE.md) §5).

1. **`past_journeys` 요약 + 완료 처리** (공유 도메인) — 완료(자동/prompt/스태프) 시 요약 push + `by_dest[목적지명]` 비우기. 첫 화면 선택·관련성 헬퍼는 [lifecycle.ts](../packages/domain/src/journey-steps/lifecycle.ts).
2. **완료 확인 prompt** (A형/B형) — 발동 조건·재발동·문구.
3. **디자인 시안** — 완료 카드 + 지난 여정 도장 카드 + A/B 팝업 통일 (portal-preview).
4. **펫무브(portal)** — 지난 여정 카드(반려동물>여정), prompt, 관련성 필터.
5. **펫무브워크(admin)** — 관련성 필터(유효/만료 배지), 완료/취소·지난 여정, 수동 추가/제외.

→ 프로덕션 마이그레이션 없음. 단일 목적지 케이스는 사실상 무변경. `past_journeys`는 이번 이후 완료분부터 쌓임.

## 10. 미해결 · 추후

- 지난 여정 카드에 **발급 서류 다시보기 링크**를 넣을지 (가치 있어 보임).
- 날짜 표기 형식(점/한글) — 시안에서.
- 비일본 **편도** 자동 완료 판정은 약함 → 당분간 prompt·스태프 전환으로 커버.
- 결제 도입 시 "취소 → 담당자 확인" 보강.
