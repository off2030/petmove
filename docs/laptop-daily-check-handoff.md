# 휴일 노트북 일일 점검 설정 인계

## 목적

업무 PC를 기본 실행 기기로 유지하면서 휴일에는 개인 노트북에서 한국 시간 매일 오후 1시의 일본 검역 이메일·검사 대기 점검을 실행할 수 있게 준비한다. 1~2시는 예상 보고 시간이며 완료 시각 보장은 아니다. 블로그 문의 수집·예약 발행은 별도 작업이며 이번 인계에 포함하지 않는다.

## 노트북에서 보낼 요청

노트북에서 펫무브 저장소의 `master`를 pull하고 이 저장소를 프로젝트로 연 뒤, 다음처럼 요청한다.

> docs/laptop-daily-check-handoff.md를 읽고 휴일용 노트북 일일 점검 설정을 이어서 해줘.

Git으로 공유되는 것은 인계 문서와 업무 지침이다. 실제 예약은 노트북에서 앱 도구로 별도 설정하고, 환경변수·로그인·고객 기록·메일 검토 이력은 아래 절차에 따라 별도로 준비한다.

다음 상세 문구는 이 파일을 가져오지 못했어도 독립적으로 사용할 수 있다.

> 이 노트북에서 펫무브 휴일용 일일 점검 설정을 이어서 해줘. 기본 실행 기기는 업무 PC이고, 휴일에는 이 노트북에서 한국 시간 오후 1시에 일본 검역 이메일과 검사 대기를 확인하려고 해. 저장소 AGENTS.md와 일본 NACCS·검사 확인 스킬을 읽고 실제 체크아웃 경로에 맞춰 환경을 준비해줘. 업무 Gmail 연결, 읽기 전용 DB 조회, 필요한 의존성을 확인하고, 기존 예약과 검토 이력을 찾아 중복 설정을 피한 뒤 읽기 전용 시험까지 진행해줘. 노트북 예약이 없으면 일시중지 상태로 준비하고, 실제 활성화는 휴일 일정과 업무 PC의 실행 여부를 맞춘 뒤 진행해줘. 이메일은 새 관련 메일 전체와 기존 미완료 건을 발신 답장·후속 회신까지 대조하고, 애매하거나 자동 처리 불가능한 새 요청은 보고해줘. 실제 정기 운영에서는 확정된 일본 수출검역 예약 날짜·시간이 펫무브워크와 모두 일치할 때만 해당 수출 상태를 완료 처리하고 재조회할 수 있어. 시험에서는 상태를 변경하지 말고 이 예외는 적용하지 마. 메일 발송·초안 저장·업로드·신규 신고·예약 일시 변경·검사 신청·결제는 하지 마. 검사 지연은 한국 날짜 기준 waiting이면서 검사일부터 달력일 5일 이상 지난 건만 보고하고, 미래 검사일·testing은 제외해줘. 메일 검토 이력과 미완료 기록은 업무 PC에서 안전하게 이어받을 방법도 마련해줘. 비밀키·로그인 정보·고객 업무 기록은 Git에 넣거나 출력하지 마. 두 기기의 자동 전환을 전제로 하지 말고 하루에 한 기기만 실행하도록 준비해줘.

## 환경 확인과 시험

1. 실제 저장소 루트와 현재 Git 상태를 확인한다. 경로를 업무 PC의 `C:\dev\petmove`로 고정하지 않는다. 기존 변경과 미공유 커밋을 보존한다. 다른 기기에 공유할 때 관련 없는 커밋까지 일괄 push하지 않는다.
2. 저장소 `AGENTS.md`, `.agents/skills/petmove-japan-naccs/SKILL.md`, `.agents/skills/petmove-inspection-check/SKILL.md`와 필요한 참조를 읽는다. 개인 스킬보다 저장소 버전을 우선한다. 최신 업무 지침이나 조회 스크립트가 없으면 업무 PC에서 가져올 항목을 명시하며 운영 기준을 추측하지 않는다.
3. Node.js와 저장소가 지정한 패키지 관리자를 확인한다. 검사 조회는 저장소 루트의 `scripts/inspection-lookup.mjs`를 읽기 전용으로 유지한다. 환경변수는 스크립트가 실제로 읽는 `.env.local` 또는 프로세스 환경에 별도로 구성하고 값은 출력하지 않는다. DB 마이그레이션·초기화·데이터 수정은 설정 시험에 포함하지 않는다.
4. 연결된 업무 Gmail 계정과 필요한 조회 도구를 확인한다. 같은 앱 계정 로그인만으로 브라우저 로그인·로컬 파일·환경변수가 이전됐다고 가정하지 않는다. 브라우저가 필요한 작업을 추가로 맡길 때에만 Chrome 연결과 해당 기관 로그인을 점검한다.
5. 실제 데이터로 읽기 전용 시험을 한다. 전체 검사 현황은 활성 조직의 비삭제 케이스를 안정적인 정렬과 명시적 페이지 범위로 끝까지 조회하고 정확한 DB 건수와 대조한다. 현재 앱의 검사 회차별 행·상태 산출 규칙을 사용한다. 이메일 시험에서는 발신 답장과 후속 메일을 대조한다. DB 상태 변경과 외부 발송·제출은 하지 않는다.

## 일일 운영 범위

- 이메일: 이전 확인 이후 일본 검역소·관련 NACCS 새 메일 전체 및 미완료 건을 검토한다. 검색 기간을 겹치고 메시지 ID로 중복 제거하며, 결과 개수나 첫 페이지만으로 범위를 제한하지 않는다. 현재 본문을 읽어 다른 동물·여행·과거 인용문과 구분한다.
- 이미 보낸 자료와 아직 남은 일을 구분한다. 보완자료 발송은 승인·예약 확정과 다르다. 새로운 미지원 요청과 애매한 판단은 대상·요구사항·처리할 수 없는 이유·필요한 자료나 판단·기한을 보고한다. 의미 있는 변화가 없는 이메일 대기는 반복 알림하지 않는다.
- 상태 변경 예외: 명확히 확정된 해당 여행의 일본 수출검역 예약 날짜와 시간이 펫무브워크 기록과 모두 일치할 때만 해당 수출 상태를 완료로 처리하고 직접 재조회한다. 이미 완료면 유지한다. 불일치·기록 누락·불명확한 대상은 일시나 상태를 변경하지 않고 보고한다. 이 예외는 읽기 전용 설정 시험에는 적용하지 않는다. 수입 승인 완료 등 다른 상태 변경 권한으로 확장하지 않는다.
- 검사: 한국 날짜 기준 `waiting`이며 검사일로부터 달력일 5일 이상 경과한 항목을 보고한다. 검사일 당일은 0일이고 5일째를 포함한다. 미래 검사일과 `testing`은 제외하고 날짜 누락 시 추정하지 않는다. 동물·보호자·기관·검사일·경과일을 적는다. 지연 건이 남으면 하루 한 번 보고하고 없으면 검사 지연 알림을 생략한다. 검사 신청·결제·검사 상태 변경은 하지 않는다.
- 이메일 발송·답장 초안 저장·파일 업로드·새 신고 제출·예약 일시 변경은 이 정기 점검 권한에 포함하지 않는다. 승인서 다운로드·첨부나 NACCS 로그인·CAPTCHA가 필요하면 필요한 작업을 보고하고 해당 시점의 사용자 지시를 따른다.

## 예약과 기기 전환

- 노트북의 기존 예약을 먼저 조회한다. 없을 때만 휴일용 일일 점검을 일시중지 상태로 준비하고 저장된 시간·시간대·프롬프트·실행 채팅·경로를 확인한다. 예약은 앱의 지원 도구로 생성·수정하며 예약 파일을 직접 편집하지 않는다.
- 실행 기기의 전원·인터넷·앱 실행과 로컬 프로젝트 가용성을 유지한다. 두 기기 중 켜진 쪽으로 예약이 자동 이동한다고 가정하지 않는다.
- 휴일이 고정이면 기기별 실행 요일을 나눌 수 있다. 임시 휴일에는 기본 기기 예약을 중지하고 노트북 예약을 활성화하는 등 당일 한 기기만 실행하도록 맞춘다. 이 인계만으로 휴일 요일·날짜를 추정하지 않는다.
- 노트북에서 업무 PC 예약을 직접 확인·변경할 수 없는 경우 그 제한을 명시한다. 업무 PC가 꺼졌을 때 밀린 작업의 재실행 여부도 확인하기 전에는 중복 방지가 됐다고 단정하지 않는다.

## 고객 기록과 확인 이력의 인계

- 업무 PC의 기존 이메일 검토 이력은 Git에서 제외된 `work/naver-inquiries/japan-mail-review.json`에 있다. 이 파일은 운영 기록이며 코드·예시 데이터와 구분한다. 내용이나 메시지 ID를 이 문서 또는 Git에 복사하지 않는다.
- 실제 이력의 존재·최신 시점·미완료 건을 확인하고 사용자가 사용하는 비공개 전송 수단으로 노트북에 이어받는다. 계정·비밀키는 별도로 구성하며 통째로 Git에 넣지 않는다.
- 노트북이 처리한 이후 업무 PC로 돌아올 때에도 새 검토 이력·미완료 상태·당일 보고 여부를 이어받아야 한다. 이력 파일을 무조건 덮어쓰지 말고 양쪽 변경과 메시지 ID를 대조한다. 노트북 예약을 매일 활성화하기 전에 이 왕복 인계 방법을 정한다.
- 이력 인계 전에는 최초 점검 완료나 중복 제거 완료로 기록하지 않는다. 필요한 연결·권한·이력이 없으면 부족한 항목을 구체적으로 보고한다.
