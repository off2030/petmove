# 기기별 일일 점검 설정 인계

## 목적

일본 검역 이메일·검사 대기 점검을 두 기기에 나누어 실행한다. 사용자가 2026-10-22에 아래 요일을 확정했다. 시간대는 모두 한국 시간(Asia/Seoul)이다. 1~2시는 예상 보고 시간이며 완료 시각 보장은 아니다. 블로그 문의 수집·예약 발행은 별도 작업이며 이번 인계에 포함하지 않는다.

| 실행 기기 | 정기 실행 요일 | 시작 시각 |
| --- | --- | --- |
| 업무 PC | 월·화·수·금·토 | 오후 1시 |
| 개인 노트북 | 목·일 | 오후 1시 |

업무 PC 예약 ID는 `automation`이며 실행 요일 변경을 앱 도구로 반영했다. 노트북 예약은 노트북에서 환경 확인과 읽기 전용 시험을 마친 뒤 해당 기기의 앱 도구로 설정해야 한다. Git pull만으로 예약이 생성되거나 다른 기기로 이동하지 않는다.

## 노트북에서 보낼 요청

노트북에서 펫무브 저장소의 `master`를 pull하고 이 저장소를 프로젝트로 연 뒤, 다음처럼 요청한다.

> 저장소 최신 내용을 pull하고 docs/laptop-daily-check-handoff.md를 읽어서, 이 노트북의 목·일요일 오후 1시 일일 점검을 설정해줘. 환경 확인과 읽기 전용 시험을 마친 뒤 해당 요일 예약을 활성화해줘.

Git으로 공유되는 것은 인계 문서와 업무 지침이다. 실제 예약은 노트북에서 앱 도구로 별도 설정하고, 환경변수·로그인은 각 기기에서 준비한다. 고객 검토 이력은 아래의 업무용 Google Drive 비공개 파일로 이어받는다. OneDrive나 Google Drive 데스크톱 동기화 앱은 필요하지 않다.

사용자는 업무 PC 월·화·수·금·토, 노트북 목·일 오후 1시라는 정기 일정을 승인했다. 노트북에서 요일 승인을 다시 요구하거나, 준비가 끝났는데도 예전 인계 문구를 근거로 예약을 계속 중지해 두지 않는다. 실제 로그인·필수 환경·검토 이력이 준비되지 않았으면 미완료 사유와 필요한 조치를 보고하고 정상 가동을 선언하지 않는다.

## 노트북에서 즉시 1회 실행

정기 요일 이외에도 노트북에서 다음처럼 요청할 수 있다.

> 이 노트북에서 일본 검역 이메일·검사 대기 점검을 지금 한 번 실행해줘. 정기 점검과 같은 업무 범위를 적용하고 정기 예약 요일·시간은 유지해줘. 새 관련 메일과 기존 미완료 건을 확인하고, 확인 시각·검토 범위·보고 여부를 이력에 남겨줘.

- 이 요청은 현재 노트북에서 시작하는 1회 실행이며 업무 PC 채팅으로 메시지를 보내라는 요청으로 해석하지 않는다. 정기 실행 요일을 바꾸거나 추가 반복 예약을 만들지 않는다.
- 검토 이력을 먼저 확인한다. 이미 확인한 메일만 있다는 이유로 새 메일 검색이나 기존 미완료 건 재대조를 생략하지 않는다. 새로운 변화는 보고하되 같은 날 같은 검사 지연·같은 완료 상태를 중복 보고·처리하지 않는다.
- 다른 기기의 최근 검토 이력을 가져올 수 없으면 그 제한을 보고하고 다른 기기의 실행·보고·완료 여부를 추정하지 않는다. 일반 운영 범위의 확정된 수출 예약 일치 시 완료 처리 예외는 적용하되, 자료가 불명확하면 상태를 바꾸지 않는다. 사용자가 읽기 전용 점검을 지정하면 그 제한을 우선한다.
- 같은 날 업무 PC의 정기 실행도 예정되어 있다면 수동 실행 기록을 그 기기에서도 이어받도록 한다. 이력 공유가 준비되지 않았으면 자동 중복 방지가 된 것으로 안내하지 않는다.

## 환경 확인과 시험

1. 실제 저장소 루트와 현재 Git 상태를 확인한다. 경로를 업무 PC의 `C:\dev\petmove`로 고정하지 않는다. 기존 변경과 미공유 커밋을 보존한다. 다른 기기에 공유할 때 관련 없는 커밋까지 일괄 push하지 않는다.
2. 저장소 `AGENTS.md`, `.agents/skills/petmove-japan-naccs/SKILL.md`, `.agents/skills/petmove-inspection-check/SKILL.md`와 필요한 참조를 읽는다. 개인 스킬보다 저장소 버전을 우선한다. 최신 업무 지침이나 조회 스크립트가 없으면 업무 PC에서 가져올 항목을 명시하며 운영 기준을 추측하지 않는다.
3. Node.js와 저장소가 지정한 패키지 관리자를 확인한다. 검사 조회는 저장소 루트의 `scripts/inspection-lookup.mjs`를 읽기 전용으로 유지한다. 환경변수는 스크립트가 실제로 읽는 `.env.local` 또는 프로세스 환경에 별도로 구성하고 값은 출력하지 않는다. DB 마이그레이션·초기화·데이터 수정은 설정 시험에 포함하지 않는다.
4. 연결된 업무 Gmail 계정과 필요한 조회 도구를 확인한다. 같은 앱 계정 로그인만으로 브라우저 로그인·로컬 파일·환경변수가 이전됐다고 가정하지 않는다. 브라우저가 필요한 작업을 추가로 맡길 때에만 Chrome 연결과 해당 기관 로그인을 점검한다.
5. 실제 데이터로 읽기 전용 시험을 한다. 전체 검사 현황은 **로잔동물의료센터 조직만** 대상으로 비삭제 케이스를 안정적인 정렬과 명시적 페이지 범위로 끝까지 조회하고 정확한 DB 건수와 대조한다. 셀프서비스용 `펫무브` 조직은 유료 대행 업무가 아니므로 검사 대기 점검·보고 대상에서 제외한다. 현재 앱의 검사 회차별 행·상태 산출 규칙을 사용한다. 이메일 시험에서는 발신 답장과 후속 메일을 대조한다. DB 상태 변경과 외부 발송·제출은 하지 않는다.

## 일일 운영 범위

- 이메일: 이전 확인 이후 일본 검역소·관련 NACCS 새 메일 전체 및 미완료 건을 검토한다. 검색 기간을 겹치고 메시지 ID로 중복 제거하며, 결과 개수나 첫 페이지만으로 범위를 제한하지 않는다. 현재 본문을 읽어 다른 동물·여행·과거 인용문과 구분한다.
- 이미 보낸 자료와 아직 남은 일을 구분한다. 보완자료 발송은 승인·예약 확정과 다르다. 새로운 미지원 요청과 애매한 판단은 대상·요구사항·처리할 수 없는 이유·필요한 자료나 판단·기한을 보고한다. 의미 있는 변화가 없는 이메일 대기는 반복 알림하지 않는다.
- 펫무브워크의 케이스 조회와 허용된 상태 변경은 **로잔동물의료센터 조직에서만** 수행한다. 셀프서비스용 `펫무브` 조직에는 운영 작업이나 상태 변경을 하지 않는다.
- 상태 변경 예외: 명확히 확정된 해당 여행의 일본 수출검역 예약 날짜와 시간이 펫무브워크 기록과 모두 일치할 때만 해당 수출 상태를 완료로 처리하고 직접 재조회한다. 이미 완료면 유지한다. 불일치·기록 누락·불명확한 대상은 일시나 상태를 변경하지 않고 보고한다. 이 예외는 읽기 전용 설정 시험에는 적용하지 않는다. 수입 승인 완료 등 다른 상태 변경 권한으로 확장하지 않는다.
- 검사: **로잔동물의료센터 조직만** 조회·보고한다. 셀프서비스용 `펫무브` 조직의 건은 조회 결과와 지연 알림에 포함하지 않는다. 한국 날짜 기준 `waiting`이며 검사일로부터 달력일 5일 이상 경과한 항목을 보고한다. 검사일 당일은 0일이고 5일째를 포함한다. 미래 검사일과 `testing`은 제외하고 날짜 누락 시 추정하지 않는다. 동물·보호자·기관·검사일·경과일을 적는다. 지연 건이 남으면 하루 한 번 보고하고 없으면 검사 지연 알림을 생략한다. 검사 신청·결제·검사 상태 변경은 하지 않는다.
- 이메일 발송·답장 초안 저장·파일 업로드·새 신고 제출·예약 일시 변경은 이 정기 점검 권한에 포함하지 않는다. 승인서 다운로드·첨부나 NACCS 로그인·CAPTCHA가 필요하면 필요한 작업을 보고하고 해당 시점의 사용자 지시를 따른다.

## 예약과 기기 전환

- 노트북의 기존 예약을 먼저 조회하고 같은 일일 점검이 있으면 수정한다. 없을 때만 새 예약을 생성한다. 환경 확인·읽기 전용 시험·검토 이력 인계 준비를 마치면 목·일 오후 1시 예약을 활성화하고 저장된 요일·시각·한국 시간대·프롬프트·실행 채팅·경로를 재확인한다. 예약은 앱의 지원 도구로 생성·수정하며 예약 파일을 직접 편집하지 않는다. 예약의 업무 프롬프트에는 이 문서의 전체 운영 범위와 예외를 포함한다.
- 실행 기기의 전원·인터넷·앱 실행과 로컬 프로젝트 가용성을 유지한다. 두 기기 중 켜진 쪽으로 예약이 자동 이동한다고 가정하지 않는다.
- 정기 예약은 업무 PC 월·화·수·금·토, 노트북 목·일로 나눈다. 실제 실행 직전 한국 날짜의 요일을 확인해 담당 요일 밖에 밀린 정기 실행이 시작되면 실제 업무 처리를 생략한다. 사용자의 명시적인 즉시 1회 점검 요청은 요일과 관계없이 수행할 수 있다. 임시로 정기 담당 기기를 변경해 달라는 별도 지시가 있으면 지정한 날짜·범위만 조정한다.
- 노트북에서 업무 PC 예약을 직접 확인·변경할 수 없는 경우 그 제한을 명시한다. 업무 PC가 꺼졌을 때 밀린 작업의 재실행 여부도 확인하기 전에는 중복 방지가 됐다고 단정하지 않는다.

## 고객 기록과 확인 이력의 인계

공유 원본은 업무용 계정 `lvmcfile@gmail.com`의 Google Drive에 있다. 2026-10-22에 업무 PC의 기존 이력을 올리고, 동일 파일 ID로 갱신한 뒤 다시 내려받아 원본과 바이트 단위로 일치함을 확인했다. 폴더와 파일의 공유 권한은 해당 계정 소유자만이다. 실제 이력 내용과 메시지 ID는 Git에 넣지 않는다.

- 위치: `내 드라이브 / Petmove-Backups / 펫무브워크 / PETMOVE 자동화 이력`
- 폴더: [PETMOVE 자동화 이력](https://drive.google.com/drive/folders/1e6MLQnV4Y7t4tA9qZ7UxUUzZktiPn3PL)
- 파일: [japan-mail-review.json](https://drive.google.com/file/d/1TC5PWYeBOsRiUzUc4kW3yDk5QpVWrxgf/view)
- 파일 ID: `1TC5PWYeBOsRiUzUc4kW3yDk5QpVWrxgf`
- 폴더 ID: `1e6MLQnV4Y7t4tA9qZ7UxUUzZktiPn3PL`
- 로컬 작업 사본: 각 저장소 루트의 `work/naver-inquiries/japan-mail-review.json`(Git 제외)

이력 폴더는 사용자가 지정한 `Petmove-Backups / 펫무브워크` 아래로 이동했다. 기존 폴더 ID와 이력 파일 ID·링크는 유지된다. 업무 PC와 노트북 모두 위의 동일 파일을 이어서 사용하며, 위치 변경 때문에 새 파일을 만들거나 이력을 초기화하지 않는다.

1. 정기·수동 점검 시작 전에 연결된 Google Drive 도구에서 업무 계정을 선택하고, 이 파일 ID의 메타데이터와 최신 원본 JSON을 읽는다. 다른 계정의 동명 파일이나 로컬 사본을 공유 원본으로 간주하지 않는다. `fetch`의 텍스트가 비어 있어도 파일이 비었다고 판단하지 말고 raw-file 다운로드를 사용한다. 다운로드 참조는 로컬 비공개 경로에만 materialize하고 서명된 다운로드 URL·인코딩된 본문을 출력하거나 Git에 저장하지 않는다.
2. JSON 문법과 기존 필드(`checkedOn`, `account`, `latestReceived`, `reviewedMessageIds`, `pending`, `completed`, `automationMode`)를 확인한다. 업무 계정과 맞는지 검증하고, 로컬 사본이 있으면 먼저 비공개 백업을 남겨 비교한다. 메시지 ID는 합집합으로 보존하고 미완료·완료 상태는 최신 메일 근거를 대조한다. 파일 수정 시각만으로 내용을 무조건 덮어쓰거나 미검토 메일을 검토 완료로 만들지 않는다.
3. 점검은 이력과 실제 Gmail 발신·수신·후속 회신, 펫무브워크의 현재 상태를 함께 확인한다. 이력 파일에 기록돼 있다는 것만으로 메일 요구사항이 해결됐다고 단정하지 않는다. 확인 시각·검토 범위·당일 검사 지연 보고 여부도 남긴다.
4. 종료 전 원격 메타데이터와 최신 이력을 다시 읽어 다른 기기의 갱신을 확인하고 병합한다. 실행이 겹치거나 변경 내용을 확실히 병합할 수 없으면 다른 기기의 기록을 덮어쓰지 않는다. 로컬 결과와 고유 이름의 실행별 JSON 백업을 비공개로 보존하고 충돌·저장 대기를 보고한다. 중지나 오류를 완료로 기록하지 않는다.
5. 같은 원격 파일 ID를 `update_file`의 raw-file 교체 기능으로 갱신한다. 매번 새로운 동명 공유 원본을 만들거나 파일·폴더의 공개 범위를 넓히지 않는다. 저장 후 메타데이터와 JSON을 다시 읽어 내용이 일치하는지 검증한다. 실패하면 로컬 결과를 보존하고 동기화 미완료를 보고한다. 다음 실행에서 성공한 것으로 가정하지 않는다. 이 절차는 자동화 프롬프트에도 포함한다.

노트북에서는 이 원격 파일을 읽어 검증하고 로컬 사본을 복원하면 최초 이력 인계 조건을 충족한다. 이전 지침에 따라 생성한 노트북 예약이 이력 부재 때문에 중지되어 있다면, Google Drive 연결·이력 읽기/동일 파일 갱신 경로를 확인하고 목·일 오후 1시 예약을 활성화한다. 이미 승인된 요일·업무 범위에 대해 추가 승인을 요구하지 않는다. 활성화 후 저장된 요일·시각·상태를 재조회한다. 필요한 계정 연결·권한·이력이 없으면 그 구체적인 원인을 보고한다.
