# 콘텐츠

문의 수집 → 중복·개인정보 점검 → 정보 검증 → 글 작성 → 검토·예약 → 실제 저장 결과 확인 순서로 진행한다. 채널을 늘려도 각 문의·글을 식별해 중복 수집·발행을 방지한다.

- 카카오톡 문의 선별·로컬 대기열 저장: [petmove-kakao-inquiries](../../.agents/skills/petmove-kakao-inquiries/SKILL.md).
- 문의를 글로 작성·네이버 저장/예약: [petmove-naver-post](../../.agents/skills/petmove-naver-post/SKILL.md).
- 홈페이지의 안내문·콘텐츠 작성은 이 영역이다. 페이지나 기능 자체를 만드는 일은 [개발](development.md)과 구분한다.

현재 정기 콘텐츠 예약의 요일·수량·검토 표시·발행 검증 기준은 실제 예약 프롬프트와 해당 스킬을 확인한다. 업무 분류를 바꾸는 것만으로 발행 권한·수량·일정을 확대하지 않는다. 고객 문의와 처리 이력은 기존 비공개 경로를 사용하고 Git에 넣지 않는다.

콘텐츠가 실제 고객의 미해결 업무를 다룬다고 해서 그 글 작업이 해당 케이스의 검사·신고 상태를 변경할 권한이 되지 않는다. 실무 처리가 필요하면 대상과 요청 범위를 구분한다.
