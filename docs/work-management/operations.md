# 펫무브워크 실무

## 공식 상태는 펫무브워크 하나

검사·수입신고·수출신고 등의 공식 상태는 펫무브워크의 실제 저장값을 유일한 기준으로 사용한다. 따로 만든 작업표·대화·Drive JSON의 `완료`, `대기` 같은 표기를 독립적인 검사/신고 상태로 운영하지 않는다. 화면에 보이는 상태도 해당 케이스·여행·검사 회차의 저장값과 앱의 산출 규칙을 확인한다.

보조 기록은 **남은 할 일·자료/회신 대기 사유·다음 행동·기한·확인 근거**를 설명한다. 예를 들어 공식 수출 상태가 `진행`이면 보조 기록에 `검역소의 예약 확정 회신 대기`라고 쓸 수 있다. 보조 기록에서 먼저 수출을 완료로 확정하지 않는다. 확정 근거와 위임 조건을 충족하면 펫무브워크를 갱신하고, 재조회한 저장 결과를 기록한다.

외부 기관의 실제 처리 결과와 펫무브워크가 다르면 그 차이는 해결할 대상이다. 공식 기록이 맞다는 이유로 실제 기관 근거를 무시하지 않는다. 권한 안에서 정정·반영하고 확인하며, 반영 권한·연결이 없으면 양쪽 근거와 미반영 사유를 보고한다. 상태를 일치시키겠다는 이유만으로 수정 권한을 확대하지 않는다.

## 조회값은 화면·PDF의 실제 선택 규칙으로 해석

DB 직접 조회를 기본으로 유지하되, 조회한 원시 컬럼 하나를 곧바로 현재 업무 값으로 간주하지 않는다. 해당 화면·PDF가 현재 사용하는 필드, 여행지 범위, 검사 회차, 우선순위와 폴백을 확인해 같은 규칙으로 해석한다. 조회 스크립트의 요약값도 이 규칙과 일치하는지 확인한다.

| 항목 | 확인할 실제 구현과 기준 |
| --- | --- |
| 보호자 영문명 | `apps/admin/components/cases/customer-name-row.tsx`의 표시와 `apps/admin/lib/pdf-fill.ts`의 `readSource`를 따른다. `data.customer_first_name_en`·`data.customer_last_name_en`이 우선이며, 이전 합본 `customer_name_en`은 해당 구현의 폴백이다. 일부만 입력된 경우도 구현대로 읽고 필수 성/이름 충족 여부를 별도로 확인한다. |
| 출국일·내원일·여행지별 정보 | `packages/domain/src/destination-scoped-fields.ts`의 `getDepartureDate`, `getVetVisitDate`, `flattenCaseForDestination`, `readScopedWithLegacyFallback` 등 해당 소비자가 쓰는 함수를 따른다. 대상 여행지를 먼저 확정하고 `by_dest`와 이전 필드의 폴백 허용 조건을 적용한다. 다른 여행지·top-level 값을 임의로 섞지 않는다. |
| 검사 행·회차별 상태 | `apps/admin/components/todos/todos-app.tsx`의 행 구성과 `apps/admin/lib/inspection-status.ts`의 상태 판정을 따른다. 첫 배열 항목·이전 단일 상태만으로 재검사 전체를 판단하지 않는다. |
| 수입·수출 상태 | `apps/admin/lib/report-status.ts`의 `reportSlotStatusFor`를 대상 여행지별로 적용한다. 첨부·절차 값으로 산출되는 상태와 이전 수동 컬럼을 구분한다. |

누락·불일치·발송 보류를 보고하기 **전에** 대상 조직/케이스/여행/회차 → 실제 소비 코드의 값 선택 규칙 → 최신 저장값의 해석 결과 순서로 재확인한다. 정상 우선 필드와 다른 과거 폴백 값이 남아 있다는 이유만으로 사용자에게 수정을 요구하거나 처리를 보류하지 않는다. 실제 사용값이 증빙과 다를 때만 업무 불일치로 보고한다.

화면과 PDF가 서로 다른 값을 선택하면 양쪽의 사용값·출처를 구분하여 확인하고 임의로 한쪽을 정답으로 단정하지 않는다. 기존 PDF가 한글명·오늘 날짜 등으로 자동 대체한 것은 영문명·내원일이 실제로 등록되었다는 근거가 아니다. 새 조회 경로에서는 필요한 필드와 해당 해석 함수를 함께 읽고, 경로를 검증할 수 없으면 그 항목만 확인 불가로 보고한다. 이 확인을 위해 운영 데이터를 자동 정정하지 않는다.

## 케이스 실행 순서

1. 로잔동물의료센터 조직과 실제 케이스·여행·대상 동물·출발국/도착국·왕복 구간을 확인한다. 현재 정기 실무 점검은 로잔 조직에 한정하고 셀프서비스용 `펫무브` 조직을 제외한다. 현재 화면의 조직이나 동물 이름 하나만으로 대상이 확정됐다고 판단하지 않는다.
2. 펫무브워크 현재 상태와 자료를 직접 읽기 전용 조회로 확인한다. 검사 회차·여행지별 값을 앱 규칙대로 확인하며, 전체 현황은 정확 건수와 전체 페이지를 대조한다. Git의 코드·예시·오래된 기록을 실제 케이스 자료로 취급하지 않는다.
3. 해당 작업의 공통 절차·국가 규칙·기관 조작 지침을 읽고 현재 요청의 범위를 확인한다. 자료 확인·작성/임시저장·신청 제출·메일 발송·일정 변경·상태 반영을 구분한다. 기존에 위임된 작업은 해당 조건이 충족되면 진행하고 같은 승인을 반복 요구하지 않는다. 조회·시험만 요청했다면 그 제한을 우선한다.
4. 필요한 자료를 대조해 가능한 작업을 실행한다. 자료 부족이나 새로운 기관 요구를 지어내어 해결하지 않고, 남은 자료·사용자 판단·기한을 정리한다.
5. 실제 결과와 해당 스킬의 상태 반영 조건을 확인한다. 위임된 경로로 기존 필드의 해당 항목만 갱신하며 다른 여행·검사 회차·다른 기관의 값을 덮어쓰지 않는다. 조회 스크립트는 읽기 전용으로 유지한다.
6. 저장 결과를 직접 재조회한다. 성공을 확인한 뒤에만 펫무브워크 반영 완료로 보고한다. 저장 실패·불일치가 있으면 실제 실행 결과와 미반영 상태를 구분한다.
7. 남은 할 일과 근거를 기존 케이스 메모·지원되는 기록 경로 또는 비공개 공유 이력에 남긴다. 메모 변경이 허용되지 않은 조회 전용 실행에서는 사용자에게 보고하고, 허용된 점검 이력만 기록한다. 기존 메모를 통째로 덮거나 정리한다는 이유로 고객 자료를 삭제하지 않는다.

## 보조 기록 양식

아래는 개인정보 없는 양식이다. 실제 작성 내용은 Git에 저장하지 않는다.

```text
대상: 조직 / 케이스·여행 식별자 / 검사 회차 또는 신고 항목
펫무브워크 현재 상태: [조회한 기존 값과 조회 시각; 조회 사본]
이번 요청과 허용 범위:
확인 근거: [관련 메일·기관 결과·문서와 확인 시각]
실제 수행한 일:
펫무브워크 반영 결과: [변경한 기존 항목과 재조회 결과 / 미반영 사유]
남은 할 일:
기다리는 자료·회신과 다음 확인 시점:
필요한 사용자 판단:
재개 위치·담당 기기·마지막 확인 시각:
```

공식 상태를 인용한 줄은 조회 시점의 사본이다. 이후 실행은 반드시 펫무브워크를 다시 읽고, 사본과 다르면 최신 저장값과 실제 근거를 대조한다. `AI 처리 상태`, `별도 신고 완료` 같은 중복 공식 상태를 추가하지 않는다.

## 정기 점검과 기기 인계

2026-10-30 사용자 지시에 따라 매일 정기 실무 점검은 **검사·신고·서류 세 탭 전체**를 확인한다. [세 탭 점검 기준](../../.agents/skills/petmove-inspection-check/references/daily-three-tabs.md)에 따라 실제 조직·전체 페이지·화면의 값 선택 규칙을 적용한다. 일본 메일·검사 지연만 확인하고 세 탭을 모두 봤다고 보고하지 않는다. 출국일이 지났어도 귀국일이 남은 일본 수출검역을 누락하지 않으며, 서류탭 상태 확인과 PDF 원본 검토는 구분한다. 이 지시는 새 신고 제출·일반 상태 변경 권한을 확대하지 않는다.

업무 PC 월·화·수·금·토, 노트북 목·일 오후 1시 일정을 유지한다. 지정 기기가 꺼져 있다고 다른 기기로 자동 이동한다고 가정하지 않는다. 수동 1회 요청은 정기 일정과 구분하고 동일 케이스·항목의 동시 수정과 중복 보고를 피한다.

기기 간 검토 이력은 [기기별 점검 인계](../laptop-daily-check-handoff.md)의 비공개 Google Drive 파일을 사용한다. 이력의 역할은 재개·중복 방지이며 검사·신고의 공식 상태는 펫무브워크에 있다. 업무 자동화 채팅은 콘텐츠 실행과 구분하고 현재 범위·근거·저장 결과를 보고한다.
