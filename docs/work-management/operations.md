# 펫무브워크 실무 운영 기준

이 문서는 대상·권한·기록·보고 기준이다. 기기·예약·공유 파일은 [인계 지침](../laptop-daily-check-handoff.md), 정기 실행과 누락 검증은 [정기 점검 스킬](../../.agents/skills/petmove-daily-review/SKILL.md), 기관 조작은 업무별 스킬이 맡는다. 규칙 변경은 해당 절을 수정하며 과거 날짜별 지시를 덧붙이지 않는다. 현재 사용자 지시가 우선한다.

## 담당과 인계

개별 실무와 정기 점검은 [검사](inspection.md), [일본 수입신고](japan.md)(수출 포함), [서류 및 기타](documents.md)의 담당 채팅에서 각각 진행한다. 세 예약은 자기 담당 전체를 검증하며 이전 통합 예약은 중지한다. 명시적 수동 전체 점검은 all scope로 수행한다. 담당·예약 생성이 신규 고객 신청·발송의 포괄 지시는 아니다.

여러 담당이 필요한 케이스는 조직·케이스·여행/검사 회차·현재 처리 주체·권한·원본 위치·다음 행동·기한을 같은 비공개 공유 이력에 남긴다. 새 기록에는 `workArea`를 `inspection`, `japan`, `documents` 중 하나로 적어 담당을 표시할 수 있다. 이는 분류 메타데이터이며 검사/신고 공식 상태가 아니다. 이전 기록은 삭제·완료 처리하지 말고 현재 작업 내용으로 담당을 판정한다.

같은 케이스의 저장이나 같은 기관 신청·발송을 동시에 실행하지 않는다. 세 담당은 같은 시각에 시작하므로 `scripts/review-lock.mjs`의 case:<caseId> 잠금과 history 잠금을 [담당별 검증 절차](../../.agents/skills/petmove-daily-review/references/daily-three-tabs.md)에 따라 사용한다. 공유 사본은 실행별 폴더에 두고 잠금 획득 후 최신 원본을 다시 읽어 자기 변경만 병합한다. 다른 채팅이 처리 중이거나 공유 최신본이 달라졌으면 실제 결과부터 재확인한다. 인계만으로 신청·발송 권한을 확대하지 않으며, 다른 채팅으로 메시지를 보내는 행위는 사용자 지시와 앱 도구 권한을 따른다.

## 대상과 공식 상태

- 정기 업무는 **로잔동물의료센터**만 대상이다. 실제 조직 ID를 확인해 모든 조회·재조회·허용된 변경에 명시한다. 셀프서비스 `펫무브` 조직과 다른 조직은 제외한다. 카카오 채널명과 DB 조직명은 다를 수 있다.
- 검사·수입·수출·서류의 공식 상태는 **Work 현재 저장값과 앱의 산출 규칙**이다. 기관 결과가 다르면 양쪽 근거를 대조해 위임 범위에서 반영·재조회한다.
- 보조 이력에는 다음 행동·기한·대기 이유·확인 근거·재개 위치를 기록한다. 별도 공식 검사/신고 상태를 운영하지 않는다. 조회 사본에는 확인 시각을 붙인다.
- 고객·칩번호·첨부·메일 원문·로그인/카드 정보·서명 URL은 Git·공개 로그에 넣지 않는다. 작업 파일은 Git 제외를 확인한 `work/naver-inquiries/` 아래에 둔다.

## 조회값은 화면·PDF의 실제 선택 규칙으로 해석

구성된 DB·스크립트·연결 도구의 읽기 전용 조회가 기본이다. 원시 컬럼·과거 대화·요약 파일은 현재 화면/PDF의 값 선택 규칙을 대신하지 않는다. 직접 조회가 실패하면 사유를 알리고 필요한 범위만 Chrome으로 확인한다.

| 항목 | 실제 소비 기준 |
| --- | --- |
| 보호자 영문명 | `customer-name-row.tsx`, `pdf-fill.ts`: `data.customer_first_name_en`/`customer_last_name_en` 우선, 이전 합본은 폴백. 정상 분리값과 다른 과거 합본만으로 불일치라고 하지 않는다. 공동 보호자도 실제 출력 기준으로 확인한다. |
| 여행별 날짜·주소 | `destination-scoped-fields.ts`의 `getDepartureDate`, `getVetVisitDate`, `flattenCaseForDestination` 등. 여행 토큰·by_dest·허용된 폴백을 먼저 확정한다. |
| 검사 회차·기관·상태 | `todos-app.tsx` 행 구성, 현재 조직 검사 설정, `inspection-status.ts`. 재검사 인덱스·전염병검사 여행지를 구분한다. |
| 수입·수출 | `import-report-selection.ts`, `report-status.ts`. 한쪽 완료가 다른 쪽·다른 여행을 가리지 않는다. |
| 서류 준비·내원 | `todos-app.tsx` 서류 선택 함수. 준비 완료, Form AC 발신, 사전 검토 통과, 진찰·정부 확인은 각각 다르다. |
| 접종 제품 | 기록의 직접 값과 조직 백신 카탈로그의 날짜별 기본값을 UI/PDF와 동일하게 해석한다. 타 병원 기록을 본원 기본값으로 대체하지 않는다. |

누락·불일치 보고 전 **조직 → 케이스 → 여행/회차 → 소비 규칙 → 최신 저장값**을 재확인한다. PDF가 누락 날짜를 오늘로 채운 것은 실제 진료 근거가 아니다. 증빙·PDF·화면이 충돌하면 출처를 구분하고 임의로 맞추지 않는다.

## 권한

검사 담당은 모든 작업을 Work 검사탭의 현재 회차·저장값을 기준으로 진행하며 대기 → 진행 → 완료를 감독한다. 검사 신청 지시를 받으면 기관 신청을 진행·저장 확인한 뒤 사용자에게 대상·기관·신청번호·금액/결제 경로와 함께 결제를 요청한다. 결제와 그 이후 진행 전환은 기존 사용자 담당을 유지하며, 신청 저장만으로 진행으로 바꾸지 않는다.

매일 기관 검사가 끝나 결과지가 Work에 입력된 회차를 확인하고 원본과 고객을 대조한다. 기존 카카오 방에서 결과 안내문과 결과지를 발송·재조회한 **뒤** 해당 검사 회차를 완료로 반영·재조회한다. 이 결과 발송은 사용자가 상시 지시한 업무이므로 매번 문구 확인·별도 발송 승인을 다시 요구하지 않는다. 이미 보낸 결과는 재발송하지 않으며, 기존 완료를 대기/진행으로 되돌리지 않는다. 대상/회차/원본 불일치, 기준치 미달·판독 불가, 방 식별 불가, 발송 실패·불명확, 유효한 개별 중단 지시는 특이사항으로 보고하고 완료를 앞당기지 않는다.

검사 매일 보고는 검사일에서 달력일 5일 이상 지났는데 Work가 waiting인 케이스(당일=0, 5일째 포함), 신청 후 결제 요청, 결과 발송·완료 처리 결과, 별도 판단·조치가 필요한 특이사항으로 한정한다. 정상 진행·예정 검사는 내부 확인 근거와 다음 행동을 남기고 `monitored`로 관리하며, 과거 보고 증거가 없다는 이유로 매번 나열하지 않는다. 기관 공지·대상과 연결되지 않은 메일은 Work 업무에 실제 영향이 있을 때만 특이사항에 포함한다.

| 작업 | 실행 범위와 확인 근거 |
| --- | --- |
| 정기 점검 | 검사·일본 수입신고·서류 및 기타의 각 담당 범위 전체, 관련 수신·발신, 미완료·중단 지시 조회·대조·보고. 아래 상시 위임만 실행한다. |
| 기존 개별 지시 재개 | 대상·작업·범위가 분명한 유효한 지시는 다음 실행에도 이어진다. 중복 확인 후 재개한다. 정기 점검의 신규 포괄 제출 금지를 기존 지시 취소로 해석하지 않는다. CAPTCHA 등 해당 시점 확인은 이유·재개 위치와 함께 요청한다. |
| 새 검사 신청 | 특정 대상 신청 지시에 따라 작성·제출·기관 저장 재확인 후 사용자에게 결제를 요청한다. 결제는 사용자 담당이며 신청 저장만으로 Work를 진행으로 전환하지 않는다. |
| 검사 결과 안내 후 완료 | 위 검사 담당 순서대로 원본·현재 회차 대조 → 카카오 안내문·결과지 발송 → 실제 발송 재조회 → 해당 Work 회차 완료·직접 재조회. 결과값/파일 등록만으로 먼저 완료 처리하지 않는다. |
| 일본 신고·수정 | 특정 여행 제출/수정 지시가 있을 때 실행. 귀국편이 등록된 왕복은 명시적 제한이 없으면 수입 Notification·Apply와 수출 신청을 함께 처리한다. 실제 신청 완료·번호 확인 후 해당 Work 슬롯을 진행으로 반영·재조회한다. |
| 일본 수입 승인 | 현재 본문·대상 여행의 명확한 승인 시 수입 완료 반영·재조회. 원본 승인서 다운로드·대조·해당 여행 첨부·저장 재조회도 위임됨. 파일 장애는 별도 후속 작업이며 완료 상태를 되돌리지 않는다. |
| 일본 수출 예약 | 확정 날짜·시간이 Work와 모두 일치하면 수출 완료·재조회. 특정 입국일의 입국검사 직후 수출검사를 진행한다는 명확한 안내도 대상·입국일·예약일 일치 시 인정한다. 기존 시각은 보존하며 그 시각까지 확정됐다고 쓰지 않는다. 날짜/명시된 시각 불일치는 보고하고 일정 수정은 별도 지시를 따른다. |
| Form AC 사전 검토본 | 현재 여행의 명시적 요청 또는 출국 21일 전(지난 미발송은 출국 전 첫 정상 점검)에 준비·첨부·답장·발송·SENT 재확인. 일본 스킬로 검증한다. 일반 메일·최종 정부 확인본·새 자료 발송으로 확대하지 않는다. |
| 카카오 결과 안내 | 검사 담당의 상시 지시에 따라 검증한 결과 안내문·결과지를 기존 고객 방에 발송·재조회한다. 다른 고객 메시지·일반 서류·내원 안내의 권한으로 확대하지 않는다. |
| 내원 예약 요청 안내 | 출국일 0~14일 전이며 내원일이 없는 여행을 매일 경고·보고하고 기존 채팅방과 안내 문구를 준비한다. **문구 확인 후 발송**한다. 같은 여행·출국일의 실제 발송 이력을 확인해 재전송하지 않으며 내원일이 등록될 때까지 예약 회신을 추적한다. |
| 수신 자료·정보 입력 | 보관 지시와 구조화 입력 지시를 구분한다. 요청 필드·회차만 보존 병합·저장 재조회. 보관만으로 상태를 바꾸지 않는다. |
| 결제 | 청구서 수신만으로 결제하지 않는다. 지정 지급처·목적·금액·카드 승인 범위와 현재 도구 정책을 따른다. 불명확한 거래를 반복하지 않는다. |

기관 접수, 결제, 검사 진행, 결과 발급, 신고 승인, 예약 확정은 다른 사건이다. 지침/설정 변경은 고객 일괄 처리 권한이 아니다.

## 실행과 중단 인계

1. Work 현재 자료와 기관 기존 내역을 읽어 대상·중복·권한을 확정한다.
2. 위임 작업은 실행 전에 비공개 공유 이력 `delegatedTasks`에 `id,orgId,caseId,destination,task,nextAction`과 원래 지시 범위·기한을 남긴다. `pending`, `manualNaccsContinuation.remaining`도 이어받고 임의 삭제하지 않는다.
3. 가능한 작업을 수행한다. 오류에는 정상 복구를 시도하며, 불명확한 결과는 재전송·재제출 전 저장값/실제 발신부터 확인한다.
4. 기관 완료 화면·번호·SENT/채팅·저장 원본 등 해당 스킬의 근거로 완료를 판정한다. Work의 해당 항목만 변경하고 직접 재조회한다.
5. 중단 시 다음 행동·실패 단계·기한·사용자 조치·화면 재개 위치를 기록·보고한다. 실행 완료 또는 명시적 취소 근거가 있을 때만 `resolvedAt`/`cancelledAt`을 기록한다. 단순 대기·기보고를 완료로 처리하지 않는다.

## 보고와 점검 완료 조건

최종 대상은 코드가 만든 **담당 scope의 시작·종료 전체 대상 합집합**이다. 검사 warning·지연·결과 안내는 inspection, 일본 수입/수출·검역소·Form AC는 japan, 일반 서류·내원·일본 외 신고는 documents다. 담당 미분류 지시는 누락시키지 않고 분류 필요로 보고한다. 출국일 경과로 통째로 제외하거나 몇 건만 골라 별도 요약하지 않는다.

- **매일 필수:** 출국 0~14일 전 내원일 미등록, 내원 당일부터 7일 이내(0~7일 포함) 서류 준비 미완료, 미래 출국이 남은 내원일 경과 미완료, 검사일 5일 이상 waiting, 현재 경고·오류·중단 지시. 기보고·새 메일 없음으로 생략하지 않는다. 출국일 없는 과거 내원을 임박 여행으로 추정하지 않는다.
- 검사 담당의 정상 진행·예정·조치 없는 대기는 위 검사 보고 기준에 따라 `monitored`로 내부 기록한다. 그 밖의 일반 회신/자료 대기는 최신 근거를 재확인하고 실제 기보고·동일 지문이 확인될 때만 조용히 유지한다. 새 요구·불일치·판단 필요는 생략할 수 없다.
- 모든 대상에 실행 결과 또는 다음 행동·대기 이유·근거를 붙인다. 검사 담당의 정상 항목은 `monitored`, 나머지는 처리 결과 보고 / 미완료 보고 / 기보고·변화 없음 재확인으로 구분한다. 경고·중단·일일 필수 건을 `monitored`나 기보고로 숨기지 않는다.
- `scripts/daily-review.mjs render` → 공유 이력 병합·원본 재조회 → `complete`가 모두 통과해야 점검 완료다. 최종 알림은 생성된 `report.private.md`의 필수 행을 모두 포함한다. 임의 축약본으로 대체하지 않는다.
- 담당 범위·필수 소스 미조회, 누락 실패, 공유 이력 불일치는 해당 담당 점검 완료가 아니다. 다른 담당 소스를 읽은 것처럼 표시하지 않는다. 오류는 failed, 사용자 조치 대기는 needs_attention으로 달력에 기록한다.
- 세 담당 예약의 succeeded는 현재 실행의 담당 scope 검증 폴더와 dailyReviewCoverage.byArea[scope] 원본 재조회를 요구하며 입력·보고·공유 이력 해시를 재검사한다. 이는 **그 담당 점검 실행의 완료 조건**이며 모든 고객 검사/신고나 다른 담당 점검의 완료가 아니다.

명령과 파일 구조는 [세 탭 검증 절차](../../.agents/skills/petmove-daily-review/references/daily-three-tabs.md)를 따른다. 사용자가 전체 미완료 목록을 요청하면 변화 유무와 관계없이 모두 보고한다.
