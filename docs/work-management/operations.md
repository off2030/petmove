# 펫무브워크 실무 운영 기준

이 문서는 대상·권한·기록·보고 기준이다. 기기·예약·공유 파일은 [인계 지침](../laptop-daily-check-handoff.md), 정기 실행과 누락 검증은 [정기 점검 스킬](../../.agents/skills/petmove-daily-review/SKILL.md), 기관 조작은 업무별 스킬이 맡는다. 규칙 변경은 해당 절을 수정하며 과거 날짜별 지시를 덧붙이지 않는다. 현재 사용자 지시가 우선한다.

## 담당과 인계

개별 실무와 정기 점검은 [검사](inspection.md), [일본 수입신고](japan.md)(수출 포함), [서류 및 기타](documents.md), [필리핀 수입허가](philippines.md)의 담당 채팅에서 각각 진행한다. 각 예약은 자기 담당 전체를 검증하며 이전 통합 예약은 중지한다. 명시적 수동 전체 점검은 all scope로 수행한다. 담당·예약 생성이 신규 고객 신청·발송의 포괄 지시는 아니다.

여러 담당이 필요한 케이스는 조직·케이스·여행/검사 회차·현재 처리 주체·권한·원본 위치·다음 행동·기한을 같은 비공개 공유 이력에 남긴다. 새 기록에는 `workArea`를 `inspection`, `japan`, `documents`, `philippines` 중 하나로 적어 담당을 표시할 수 있다. 이는 분류 메타데이터이며 검사/신고 공식 상태가 아니다. 이전 기록은 삭제·완료 처리하지 말고 현재 작업 내용으로 담당을 판정한다.

같은 케이스의 저장이나 같은 기관 신청·발송을 동시에 실행하지 않는다. 예약 시간이 겹치는 담당은 `scripts/review-lock.mjs`의 case:<caseId> 잠금과 history 잠금을 [담당별 검증 절차](../../.agents/skills/petmove-daily-review/references/daily-three-tabs.md)에 따라 사용한다. 공유 사본은 실행별 폴더에 두고 잠금 획득 후 최신 원본을 다시 읽어 자기 변경만 병합한다. 다른 채팅이 처리 중이거나 공유 최신본이 달라졌으면 실제 결과부터 재확인한다. 인계만으로 신청·발송 권한을 확대하지 않으며, 다른 채팅으로 메시지를 보내는 행위는 사용자 지시와 앱 도구 권한을 따른다.

## 대상과 공식 상태

- 정기 업무는 **로잔동물의료센터**만 대상이다. 실제 조직 ID를 확인해 모든 조회·재조회·허용된 변경에 명시한다. 셀프서비스 `펫무브` 조직과 다른 조직은 제외한다. 카카오 채널명과 DB 조직명은 다를 수 있다.
- 검사·수입·수출·서류의 공식 상태는 **Work 현재 저장값과 앱의 산출 규칙**이다. 기관 결과가 다르면 양쪽 근거를 대조해 위임 범위에서 반영·재조회한다.
- 보조 이력에는 다음 행동·기한·대기 이유·확인 근거·재개 위치를 기록한다. 별도 공식 검사/신고 상태를 운영하지 않는다. 조회 사본에는 확인 시각을 붙인다.
- 고객·칩번호·첨부·메일 원문·로그인/카드 정보·서명 URL은 Git·공개 로그에 넣지 않는다. 작업 파일은 Git 제외를 확인한 `work/naver-inquiries/` 아래에 둔다.

## 조회값은 화면·PDF의 실제 선택 규칙으로 해석

구성된 DB·스크립트·연결 도구의 읽기 전용 조회가 기본이다. 원시 컬럼·과거 대화·요약 파일은 현재 화면/PDF의 값 선택 규칙을 대신하지 않는다. 직접 조회가 실패하면 사유를 알리고 필요한 범위만 Chrome으로 확인한다.

| 항목 | 실제 소비 기준 |
| --- | --- |
| 보호자 영문명 | `customer-name-row.tsx`, `pdf-fill.ts`: `data.customer_first_name_en`/`customer_last_name_en` 우선, 이전 합본은 폴백. 정상 분리값과 다른 과거 합본만으로 불일치라고 하지 않는다. 공동 보호자도 실제 출력 기준으로 확인한다. |
| 여행별 날짜·주소 | `destination-scoped-fields.ts`의 `getDepartureDate`, `getVetVisitDate`, `flattenCaseForDestination` 등. 여행 토큰·by_dest·허용된 폴백을 먼저 확정한다. |
| 검사 회차·기관·상태 | `todos-app.tsx` 행 구성, 현재 조직 검사 설정, `inspection-status.ts`. 재검사 인덱스·전염병검사 여행지를 구분한다. |
| 수입·수출 | `import-report-selection.ts`, `report-status.ts`. 한쪽 완료가 다른 쪽·다른 여행을 가리지 않는다. |
| 서류 준비·내원 | `todos-app.tsx` 서류 선택 함수. 준비 완료, Form AC 발신, 사전 검토 통과, 진찰·정부 확인은 각각 다르다. |

누락·불일치 보고 전 **조직 → 케이스 → 여행/회차 → 소비 규칙 → 최신 저장값**을 재확인한다. PDF가 누락 날짜를 오늘로 채운 것은 실제 진료 근거가 아니다. 증빙·PDF·화면이 충돌하면 출처를 구분하고 임의로 맞추지 않는다.

## 일본 담당 상시 업무

일본 담당은 로잔동물의료센터의 Work **신고탭에 표시되는 현재 여행별 수입·수출 항목**을 기준으로 다음 순서로 매 정기 실행을 수행한다. 이 절은 사용자가 지정한 상시 실행 지시이며, 새 대기 항목마다 별도 제출 지시를 다시 요구하지 않는다.

1. 신고탭의 전체 대상과 여행 차수별 실제 저장값을 확인한다. 이미 출국한 여행도 남은 수출·기관 후속이 있으면 추적한다.
2. 새로 올라온 **대기 항목은 신고를 진행**한다. 현재 자료·기존 NACCS 신청·발신을 대조해 중복을 막고, 필요한 수입 Notification·Apply 및 등록된 왕복의 수출 신청을 제출한다. 실제 신청번호 확인 후 해당 Work 항목을 진행으로 저장·재조회한다. 자료가 부족하거나 모순되면 해당 건만 중단하고 필요한 자료·판단을 보고한다.
3. **진행 항목은 기관 이메일과 실제 신청 진행을 확인하고 업데이트**한다. 자동 접수·검토 중·보완 요청·승인·예약 확정을 구분하고 필요한 후속을 수행한다.
4. **수입 승인서가 나오면 기관 원본을 내려받아 현재 동물·칩·여행과 대조하고 해당 여행에 저장한 뒤 수입을 완료 처리·재조회**한다. 승인과 시스템 발급 상태가 다르거나 원본 보관이 막히면 특이사항으로 보고하고 기존 완료를 되돌리지 않는다.
5. **일본 수출동물검역 예약이 확정되면 해당 수출 항목을 완료 처리·재조회**한다. 확정된 날짜·명시된 시각은 Work와 대조하며 불일치하면 임의로 일정을 맞추지 않고 보고한다.
6. **일본 검역소 이메일을 꼼꼼히 확인해 대응**한다. 현재 여행의 보완 요청·신고 정정·일정 확인·증명서·가방 사진 요청 등에 현재 확인된 Work 자료와 원본으로 필요한 회신·첨부·신고 수정을 진행한다. 새 일정·사실을 임의로 약속하지 않으며 자료 미수령·범위 불명확·특수 요구는 별도 보고한다.
7. **수입 승인 완료 메일을 확인하면 그 실행에서 바로 Form AC 사전 검토본을 준비해 해당 여행의 승인 메일 스레드에 회신·발송**한다. 출국까지 남은 일수로 발송을 미루지 않는다. 이미 승인됐지만 사전본이 미발송인 유효한 여행도 다음 점검에서 대조해 처리한다. 출국 직전에는 한국 출국 검역·정부 확인을 마친 최종 Form AC를 실제 원본으로 확보·대조해 전달한다. 검토본을 최종본으로 대체하거나 실제 진찰·정부 확인 완료를 추정하지 않는다. 각 단계의 실제 SENT·첨부를 따로 확인해 중복 발송을 막고, 자료 부족·불일치로 바로 보내지 못하면 해당 건의 이유와 다음 행동을 보고한다.
8. **특이사항은 별도로 보고**한다. 자료 부족, 신고/Work 불일치, 승인서 출력 장애, 예약 미확정·일정 불일치, 기한 위험, 인증·사용자 판단 필요와 기존 중단 작업을 대상·이유·다음 행동·기한과 함께 남긴다.

**일본 입국검사가 끝난 여행의 수입 승인서 미보관과 NACCS 승인서 출력 메뉴 종료는 새 미완료 업무나 출력 장애로 추적하지 않는다.** 입국 완료 후 과거 수입 승인서 확보만을 위해 검역소에 사본 요청·재문의를 보내지 않는다. 남은 귀국 수출검역 신청·예약과 기관의 현재 명시 요청만 이어서 처리한다. 사용자가 별도로 해당 원본 확보를 지시한 경우에는 그 범위만 수행하며, 다른 차수의 새 일본 입국 여행은 별도로 점검한다.

위임 범위의 저장·제출·발송은 기존 잠금·중복 확인·저장 재조회 절차를 지킨다. 검사·고객 카카오 발송·결제의 권한은 해당 담당 기준을 따른다. Form AC 사전 검토본의 발송 계기는 **현재 여행의 수입 승인 완료 메일 확인**이다. **진찰 예정일이 없어도 1차 사전 검토본은 발송한다.** 미정 진찰일·서명·정부 확인란은 빈칸으로 두고 메일에서 진찰일 미정과 사전 검토본임을 설명하며, 오늘 날짜나 임의 예정일을 채우지 않는다. 다른 필수 정보의 누락·불일치와 실제 최종본 요건은 별도로 확인한다. 자동 등록·접수 알림은 승인이 아니며, 검역소의 별도 사전 검토 요청도 대응한다.

## 일본 담당 보고 형식

기본 보고는 **대기 → 진행 → 완료 → Form AC 1차 → Form AC 2차** 순서로 구분한다. 같은 동물·여행은 한 행으로 묶고, 표에는 `대상(보호자)·여행 | 대기 | 진행 | 완료 | Form AC 1차 | Form AC 2차 | 다음 행동·기한`을 순서대로 배치한다. 보고 대상과 조용히 유지하는 조건은 아래 공통 기준을 따른다.

- **대기·진행·완료:** Work 현재 저장값에 따라 수입·수출을 각각 해당 칸에 표시한다. 수입 완료·수출 진행처럼 서로 다른 단계는 모두 보이게 쓰며, 수출 대상이 없는 여행은 해당 없음을 표시한다. 신고 완료를 Form AC나 고객 업무 전체 완료로 표현하지 않는다.
- **Form AC 1차:** 수입 승인 완료 메일 확인 후 회신하는 사전 검토본이다. 미발송/발송일과 검역소 검토 중·통과·보완 요청을 구분한다. 실제 SENT 확인 없이 초안 준비를 발송 완료로 쓰지 않는다.
- **Form AC 2차:** 한국 출국 검역·정부 확인을 마친 실제 최종본이다. 원본 확보 대기/발송일과 검역소 확인 여부를 구분한다. 1차 검토 통과를 2차 발송으로 표시하지 않는다.
- **예외·특이사항:** 기본 표 다음에 별도로 대상·현재 문제·오늘 조치·남은 행동·기한을 설명한다. 자료 부족, 승인서 출력 장애, 예약 미확정·불일치 등 실제 사유를 적고 정상적인 예정·일반 주의사항을 업무 중단으로 과장하지 않는다.

이 구분은 Work와 실제 발신 근거를 읽어 보여 주는 보고 형식이며 별도 공식 상태나 독립 작업대장으로 저장하지 않는다. 각 행의 수입·수출과 Form AC 두 단계는 함께 표시하므로 나중 단계의 진척으로 남은 앞 단계 업무가 가려지지 않게 한다.

## 필리핀 담당 상시 업무

사용자가 위임한 상시 업무는 **매일 10:30 한국 시간에 Work 신고탭의 필리핀 수입허가 대상 전체를 확인하고, 정보·서류·신고 시기 등 요건이 모두 완비된 건의 SPSIC를 신청하며, 신청된 동물의 승인 여부를 매일 확인·보고**하는 것이다. 업무 PC에서 목·일도 실행한다. 현재 지시는 정기 실행의 권한이며 설정 작업 자체에서 고객을 일괄 제출하지 않는다.

1. 현재 Work DB·여행 차수·서명 원본·기존 기관 신청·공유 미완료 지시를 대조한다. 하나라도 누락·모순·미확인이면 해당 건 제출을 보류하고 부족한 항목·적정 신청일·기한을 보고한다. 2027년 변경 규정 등 실제 신청·승인일에 적용될 최신 공식 요건을 확인한다.
2. 완비 건은 [필리핀 스킬](../../.agents/skills/petmove-philippines-import/SKILL.md)로 작성·첨부·검토·제출한다. 중복 신청을 막고 같은 신청을 이어간다. 유효한 상시 범위를 매번 다시 승인받지 않는다. 현재 도구가 해당 시점의 CAPTCHA·확약 확인을 요구하면 구체적인 단계와 재개 위치를 보존해 사용자에게 요청한다. 비용은 아래 결제 기준을 따른다.
3. 실제 신청번호·UNDER REVIEW 확인 후 해당 여행 수입을 진행으로 반영·직접 재조회한다. 파일 업로드·초안 저장·오류 없음은 접수가 아니다. 신청번호는 허가번호 필드에 넣지 않는다.
4. 모든 신청 미종결 건은 출국일 경과와 관계없이 매일 현재 기관 상세·보완·반려·승인 여부를 확인한다. 승인 원본 보관과 Work 수입 완료가 끝난 여행은 출국 전이어도 정기 기관 조회·유효기간 재대조·반복 보고에서 제외한다. 새 여행, 명시적 재확인 요청, 새 기관 요청 또는 실제 미해결 보관·Work 반영 불일치가 있을 때만 해당 후속을 다시 확인한다. 보완 첨부는 현재 확인된 사실·서류와 위임 범위에서 같은 신청에 진행하고, 사실 정정·취소·새 비용은 권한을 확인한다.
5. 승인된 원본 허가증을 내려받아 수입자·동물·칩·여행·유효기간을 대조하고 해당 Work 여행에 보관한 뒤 수입 완료를 저장·재조회한다. 기관 승인, 원본 보관, Work 완료는 각각 확인한다. 원본/Work 반영 실패·불일치는 특이사항과 다음 행동으로 남기며 기존 완료를 임의로 되돌리지 않는다.
6. 보고는 대상·여행별로 Work 현재 상태, 신청번호·기관 상태·오늘 확인 시각, 오늘 처리, 남은 일·기한을 한 행에 담는다. **신청 건의 승인 여부는 변화가 없어도 매일 보고**한다. 보완·반려·접속 실패·규정/자료 불일치·사용자 확인 필요는 별도 설명한다. 대상이 없으면 전체 조회 후 0건을 보고한다.

필리핀의 일반 서류·내원·임상 정보 입력은 서류 담당을 유지한다. 다른 국가 신청, 고객/기관 메시지 발송, 충전·카드 결제, 근거 없는 임상 값 수정으로 권한을 넓히지 않는다. 케이스 잠금·공유 이력 보존 병합·원본 재조회와 `--scope philippines` 누락 검증을 적용한다.

## 서류 담당 상시 업무

서류 담당은 **펫무브워크 서류 탭**을 기준으로 여행별 출국일·내원일·내원가능일·서류 준비 상태를 직접 조회하고 관리한다. 카카오 대화·원본 자료는 서류 탭과 대조하는 근거이며 별도 공식 상태를 만들지 않는다.

1. 내원일이 등록된 준비 미완료 건을 관리하며, **내원 7일 전부터 내원 당일(0~7일 포함)까지 매일 서류 준비 미완료를 경고·보고**한다. 내원일이 지났어도 미래 출국이 남은 준비 미완료 건은 계속 경고한다. 8일 이상 남은 정상 준비 대기는 내부 관리하고 매일 경고 목록에 나열하지 않는다. 내원일·보호자/동물·목적지·출국일과 준비할 서류, 확인된 누락·남은 일을 구체적으로 적는다. 준비 완료 건을 다시 준비 대상으로 올리지 않으며, 남은 출국이 없는 과거 내원은 현재 준비 건으로 추정하지 않는다.
2. **출국일만 있고 내원일이 없는 건은 출국 2주 전 카카오 예약 안내 대상**으로 관리한다. 14일 전 첫 정상 정기 실행에 안내하고, 그보다 늦게 등록되거나 해당 날짜에 정기 실행이 없으면 출국 전 다음 정상 실행에서 미발송 여부를 확인한다. 2주 넘게 남은 단순 예약 대기는 내부에서 관리하며 새 요구·불일치가 없으면 매일 목록을 나열하지 않는다.
3. 기존 고객 방과 실제 예약·발송 이력을 대조한다. 예약이 이미 수락됐는데 Work 내원일이 비어 있으면 다시 예약을 요청하지 않고 미반영 사실과 필요한 입력을 보고한다. 같은 여행·출국일의 안내는 중복 발송하지 않고 예약 회신을 추적한다. [예약 안내 절차](../../.agents/skills/petmove-daily-review/references/visit-booking.md)의 기본 문구는 사용자 승인 완료이며, 위 출국 2주 전 대상에게 해당 문구로 안내하는 상시 지시다. 대상별로 같은 발송 승인을 다시 요구하지 않는다. 실제 내원가능일·목요일/일요일 휴진·오전 10시~오후 6시 기준을 적용한다.
4. 보고는 **서류 준비 필요 / 예약 안내·회신 / 특이사항** 순서로 작성하고 같은 동물·여행은 한 행으로 묶는다. 오늘 처리한 일과 남은 일을 구분한다. 자료 부족·불일치·사용자 판단 필요는 별도로 알린다. 카카오 문의가 있다는 이유만으로 모든 건을 업무 중단이나 발송 승인 요청으로 만들지 않는다.

## 권한

검사 담당은 모든 작업을 Work 검사탭의 현재 회차·저장값을 기준으로 진행하며 대기 → 진행 → 완료를 감독한다. 검사 신청 지시를 받으면 기관 신청을 진행·저장 확인한 뒤 사용자에게 대상·기관·신청번호·금액/결제 경로와 함께 결제를 요청한다. 결제와 그 이후 진행 전환은 기존 사용자 담당을 유지하며, 신청 저장만으로 진행으로 바꾸지 않는다.

검사 결과 안내는 **상시 지시의 적용 기준 시점 이후 Work에 새로 입력되는 결과지만** 대상으로 한다. 기준 시점에 이미 있던 과거 결과지·과거 미발송 큐는 기발송 여부 조사·추가 발송·상태 보정을 하지 않는다. 발송이 미확정이거나 큐에 남았다는 이유로 과거 건을 재개하지 않으며, 다시 처리하려면 해당 과거 건을 지정한 새 지시가 필요하다. 기존 기록은 삭제하거나 발송 완료로 꾸미지 않고 공유 이력의 `kakaoResultNoticeQueue.prospectiveOnly`에 적용 시각·기존 첨부 지문·제외 큐 식별자를 보존한다.

대상 신규 결과지의 원본·현재 회차·고객을 대조하고, 발송 직전에 해당 결과의 중복 여부만 확인한다. 기존 카카오 방에서 결과 안내문과 결과지를 발송·재조회한 **뒤** 해당 검사 회차를 완료로 반영·재조회한다. 이 범위의 발송은 상시 지시이므로 매번 문구 확인·별도 승인을 다시 요구하지 않는다. 적용 이후 새 결과의 발송 실패·일부 성공만 후속으로 추적하며, 발송 확인이 끝난 과거 대화·결과는 매일 다시 확인하지 않는다. 기존 완료는 되돌리지 않는다. 대상/회차/원본 불일치, 기준치 미달·판독 불가, 방 식별 불가, 발송 실패·불명확, 유효한 개별 중단 지시는 특이사항으로 보고하고 완료를 앞당기지 않는다.

검사 매일 보고는 검사일에서 달력일 5일 이상 지났는데 Work가 waiting인 케이스(당일=0, 5일째 포함), 신청 후 결제 요청, 결과 발송·완료 처리 결과, 별도 판단·조치가 필요한 특이사항으로 한정한다. 정상 진행·예정 검사는 내부 확인 근거와 다음 행동을 남기고 `monitored`로 관리하며, 과거 보고 증거가 없다는 이유로 매번 나열하지 않는다. 기관 공지·대상과 연결되지 않은 메일은 Work 업무에 실제 영향이 있을 때만 특이사항에 포함한다.

| 내원 예약 요청 안내 | 서류 담당 상시 업무에 따라 출국일 0~14일 전이며 내원일이 없는 여행을 확인하고 승인된 기본 문구로 기존 고객 방에 예약 안내를 발송·재조회한다. 같은 여행·출국일의 실제 발송·예약 수락 이력을 확인해 재전송하지 않으며 내원일이 등록될 때까지 예약 회신을 추적한다. 방 식별 불가·날짜 모순·발송 실패는 해당 건을 중단해 보고한다. |
| 수신 자료·정보 입력 | 보관 지시와 구조화 입력 지시를 구분한다. 요청 필드·회차만 보존 병합·저장 재조회. 보관만으로 상태를 바꾸지 않는다. |
| 결제 | 청구서 수신만으로 결제하지 않는다. 지정 지급처·목적·금액·카드 승인 범위와 현재 도구 정책을 따른다. 불명확한 거래를 반복하지 않는다. |

기관 접수, 결제, 검사 진행, 결과 발급, 신고 승인, 예약 확정은 다른 사건이다. 지침/설정 변경은 고객 일괄 처리 권한이 아니다.

## 실행과 중단 인계

1. Work 현재 자료와 기관 기존 내역을 읽어 대상·중복·권한을 확정한다.
2. 위임 작업은 실행 전에 비공개 공유 이력 `delegatedTasks`에 `id,orgId,caseId,destination,task,nextAction`과 원래 지시 범위·기한을 남긴다. `pending`, `manualNaccsContinuation.remaining`도 이어받고 임의 삭제하지 않는다.
3. 가능한 작업을 수행한다. 오류에는 정상 복구를 시도하며, 불명확한 결과는 재전송·재제출 전 저장값/실제 발신부터 확인한다.
4. 기관 완료 화면·번호·SENT/채팅·저장 원본 등 해당 스킬의 근거로 완료를 판정한다. Work의 해당 항목만 변경하고 직접 재조회한다.
5. 중단 시 다음 행동·실패 단계·기한·사용자 조치·화면 재개 위치를 기록·보고한다. 실행 완료 또는 명시적 취소 근거가 있을 때만 `resolvedAt`/`cancelledAt`을 기록한다. 단순 대기·기보고를 완료로 처리하지 않는다.

## 보고와 점검 완료 조건

최종 대상은 코드가 만든 **담당 scope의 시작·종료 전체 대상 합집합**이다. 검사 warning·지연·결과 안내는 inspection, 일본 수입/수출·검역소·Form AC는 japan, 필리핀 수입허가는 philippines, 일반 서류·내원·그 외 신고는 documents다. 필리핀 수출이 있으면 documents의 기존 개별 권한을 따른다. 담당 미분류 지시는 누락시키지 않고 분류 필요로 보고한다. 출국일 경과로 통째로 제외하거나 몇 건만 골라 별도 요약하지 않는다.

- **매일 필수:** 필리핀 수입 신청 요건·신청 건 승인 여부, 출국 0~14일 전 내원일 미등록, 내원 7일 전~당일(0~7일 포함) 서류 준비 미완료, 미래 출국이 남은 내원일 경과 미완료, 검사일 5일 이상 waiting, 현재 경고·오류·중단 지시. 기보고·새 메일 없음으로 생략하지 않는다. 출국일 없는 과거 내원을 임박 여행으로 추정하지 않는다.
- 검사 담당의 정상 진행·예정·조치 없는 대기와 서류 담당의 내원 8일 이상 남은 정상 준비 대기·출국 2주 초과 내원 미등록 단순 예약 대기는 `monitored`로 내부 기록한다. 그 밖의 일반 회신/자료 대기는 최신 근거를 재확인하고 실제 기보고·동일 지문이 확인될 때만 조용히 유지한다. 새 요구·불일치·판단 필요는 생략할 수 없다.
- 모든 대상에 실행 결과 또는 다음 행동·대기 이유·근거를 붙인다. 위에서 허용한 정상 내부 대기는 `monitored`, 나머지는 처리 결과 보고 / 미완료 보고 / 기보고·변화 없음 재확인으로 구분한다. 경고·중단·일일 필수 건을 `monitored`나 기보고로 숨기지 않는다.
- `scripts/daily-review.mjs render` → 공유 이력 병합·원본 재조회 → `complete`가 모두 통과해야 점검 완료다. 최종 알림은 생성된 `report.private.md`의 필수 사실·처리 결과를 빠짐없이 포함한다. 일본 담당은 같은 동물·여행의 신고 슬롯·메일·보관 후속을 한 행으로 합쳐 현재 상태·오늘 처리·다음 행동·기한을 보고한다. 항목별 검증 ID와 근거는 비공개 보고에 보존하며, 과거 지시문·영문 작업 메모·중복 사유를 사용자에게 그대로 나열하지 않는다. 특이사항은 별도로 표시한다. 정상적인 일반 안내문을 실제 오류나 사용자 조치가 필요한 업무 중단으로 과장하지 않는다.
- 담당 범위·필수 소스 미조회, 누락 실패, 공유 이력 불일치는 해당 담당 점검 완료가 아니다. 다른 담당 소스를 읽은 것처럼 표시하지 않는다. 오류는 failed, 사용자 조치 대기는 needs_attention으로 달력에 기록한다.
- 각 담당 예약의 succeeded는 현재 실행의 담당 scope 검증 폴더와 dailyReviewCoverage.byArea[scope] 원본 재조회를 요구하며 입력·보고·공유 이력 해시를 재검사한다. 이는 **그 담당 점검 실행의 완료 조건**이며 모든 고객 검사/신고나 다른 담당 점검의 완료가 아니다.

명령과 파일 구조는 [세 탭 검증 절차](../../.agents/skills/petmove-daily-review/references/daily-three-tabs.md)를 따른다. 사용자가 전체 미완료 목록을 요청하면 변화 유무와 관계없이 모두 보고한다.
