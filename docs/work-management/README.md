# 펫무브 업무 운영 구조

## 세 영역

| 영역 | 범위 | 진입 지침 |
| --- | --- | --- |
| 앱·웹·홈페이지 개발/관리 | 보호자 앱, 펫무브워크 제품 개발, 펫무브 홈페이지 제작·디자인·기능·운영 관리, 오류 수정 | [개발](development.md) |
| 콘텐츠 | 문의 선별·정리, 정보 검증, 글 작성, 검토, 예약 발행 | [콘텐츠](content.md) |
| 펫무브워크 실무 | 실제 고객·동물·여행의 검사, 수입/수출 신고, 증명서, 검역소 메일, 보완자료 대응 | [실무](operations.md) |

사용자의 자연어 요청에서 영역과 실행 대상을 먼저 판단한다. 정해진 명령문을 사용자에게 요구하지 않는다. 홈페이지 페이지나 입력 기능을 고치는 것은 개발이며, 실제 케이스의 값을 확인·처리하는 것은 실무다. 안내 글을 작성하는 것은 콘텐츠다. 한 요청에 여러 영역이 있으면 각 영역의 작업과 결과를 구분한다.

## 상태와 기록의 기준

- **검사·수입·수출 등의 공식 업무 상태는 펫무브워크 DB의 현재 저장값 하나를 기준으로 한다.** 별도 작업표에 같은 상태를 복제해 따로 판단하지 않는다.
- 보조 기록은 다음 할 일, 필요한 자료, 대기 이유, 기한, 담당 기기, 마지막 확인 시각과 근거를 담는다. 공식 상태를 인용할 때는 조회 시각과 근거를 붙인 사본으로만 취급한다.
- 조회 → 확인된 근거 대조 → 권한 안에서 실행 → 펫무브워크 반영 → 저장 결과 재조회 → 남은 할 일 기록 순서를 따른다. 반영이 안 되면 완료로 보고하지 않고 차이와 이유를 알린다.
- 기존 앱의 메모·첨부·변경 이력 기능을 우선 활용한다. 새로운 상태 필드나 작업대장 화면을 이미 구현된 기능처럼 설명하지 않는다. 메모·파일·상태 변경에도 해당 요청의 실제 권한 범위를 적용한다.

## 국가와 작업을 조합하는 방법

국가는 적용 규칙을 정하고, 작업 유형은 실행 순서를 정한다. `조직 + 케이스/여행 식별자 + 대상 동물 + 출발국/도착국 + 왕복 구간 + 작업 + 허용 범위`를 확정하고 공통 절차·해당 국가 규칙·해당 기관 조작 지침을 조합한다. 현재 저장소에 표준화된 일본 NACCS·검사기관 업무는 기존 스킬을 사용한다. 다른 국가의 절차는 준비 여부와 최신 공식 근거를 확인해 보충하며, 기존 대화가 있었다는 이유만으로 실행 가능한 스킬이 있다고 가정하지 않는다.

## 실행과 배분

| 실행 종류 | 맡는 일 | 다른 실행으로 넘길 기록 |
| --- | --- | --- |
| 정기 실무 점검 | 새 메일·후속 회신·기존 미완료·검사 지연 확인, 기존에 위임된 예외 처리 | 대상, 근거, 다음 할 일, 필요한 판단 |
| 케이스 실행 | 지정된 케이스의 자료 확인·서류·신고 등 요청 범위 처리 | 실제 결과, 펫무브워크 저장 결과, 남은 일 |
| 콘텐츠 실행 | 문의 수집·작성·예약, 게시 결과 확인 | 문의/글 식별자, 실제 저장·예약 결과 |
| 개발 실행 | 요구 정리·구현·검증, 홈페이지 운영 변경 | 변경 파일·검증·반영 범위 |

콘텐츠와 실무 자동화의 담당 채팅을 분리하고 각 실행은 공통 진입 문서와 해당 영역 지침을 읽는다. 케이스 작업을 나눠도 같은 케이스·검사 회차·신고 항목을 동시에 수정하지 않는다. 다른 채팅으로 메시지를 보내거나 새 담당 채팅을 생성하는 행위는 앱 도구의 사용자 승인 요건을 따른다. 문서에 역할이 있다는 것만으로 별도 에이전트가 자동 실행되는 것은 아니다.

## 업무 PC의 담당 채팅과 예약

사용자가 합의한 세 영역의 담당 채팅을 같은 `petmove` 저장소 프로젝트에 만들고, 사이드바의 각 영역에 배치했다.

| 영역 | 담당 채팅 | 작업 PC 채팅 ID | 연결된 기존 예약 |
| --- | --- | --- | --- |
| 개발·홈페이지 | 펫무브 개발 · 앱·웹·홈페이지 | `01a16657-41a4-7323-9e5b-e1418e9d44c1` | 정기 실행 없음. 사용자 요청별 작업 |
| 콘텐츠 | 펫무브 콘텐츠 · 문의·글·발행 | `01a16657-7b3a-7c93-8d25-652b50693724` | 기존 `31` 예약. 월·화 오후 1시, 기존 수집·31개 보충 기준 |
| 실무 | 펫무브워크 실무 · 검사·신고·서류 | `01a16657-a7fc-7942-8b92-2cc7880d208e` | 기존 `automation` 예약. 월·화·수·금·토 오후 1시 |

기존 예약의 실제 담당 채팅을 각각 변경했다. 과거 대화와 기록은 보존한다. 이 채팅 ID는 업무 PC 실행용이며, 노트북의 예약 대상을 이 ID로 바꾸지 않는다. 노트북에서는 기존 목·일 오후 1시 담당 채팅과 예약을 사용하고 최신 공통 지침을 읽도록 확인한다. Git pull은 앱의 채팅·사이드바·예약 설정을 자동 동기화하지 않는다.

## 저장 위치

| 위치 | 역할 |
| --- | --- |
| Git | 공통 지침, 국가/기관별 절차, 코드, 개인정보 없는 양식 |
| 펫무브워크 | 실제 고객·동물·여행·검사·신고 상태와 지원되는 메모·첨부·변경 이력 |
| 비공개 Google Drive | 업무 서류와 기기 간 점검 이력·재개 정보. 공식 상태의 대체 원본으로 사용하지 않음 |
| 기기별 로컬 파일 | 작업 사본·백업·임시 출력. Git에서 제외하며 기기 간 공유 완료를 추정하지 않음 |

업무 PC·노트북의 실제 일정과 비공개 이력 연결은 [기기별 점검 인계](../laptop-daily-check-handoff.md)를 따른다. 정기 점검은 로잔동물의료센터 조직에 한정한다. 앱 개발·콘텐츠 계획을 이유로 실제 운영 데이터의 조회·변경 범위를 넓히지 않는다.

이 문서는 업무 분류·배분·기록 기준이다. 신규 작업대장 UI, 중앙 실행 잠금, 자동 업무 배정 프로그램을 구현한 문서가 아니다. 기존 자동화와 스킬을 이 기준으로 운영하고, 추가 제품 기능은 개발 작업으로 구분한다.
