## 다음에 할 일 (미결)

### 1. 문구 어투 통일 — 사용자 확인 대기
두 주의가 같은 구조("격리 없이 가려면 X, 지금 상태로는 7일 격리")인데 끝맺음이 다르다.

| 룰 | 끝맺음 |
|---|---|
| `tw.import-permit-120days-before-entry` | 지금은 도착 후 7일간 **격리되는 점 참고하세요.** (사용자 지정) |
| `tw.rnatt-180days-to-1year-before-arrival` | 지금 일정으로는 도착 후 7일간 **격리돼요.** |

항체 쪽도 "참고하세요"로 맞출지 물어봤으나 답을 못 받았다. 맞추기로 하면 한 줄 수정.

### 2. 항체 목록 UI — 실기기 검증 범위
"추가 검사 카드가 없는 목적지는 본 검사 카드가 목록을 통째로 다룬다"를 구현했는데
(EU·태국·필리핀·베트남·중국 적용), **필리핀에서만** 브라우저로 끝까지 확인했다.
나머지 4곳은 코드 경로가 같아 동작할 것으로 보지만 확인 안 함.

### 3. 이전 세션에서 넘어온 것 (그대로 유효)
- **베트남 귀국 lane** — 대만·EU 는 '귀국 서류 준비'류 카드가 있는데 베트남만 없다.
  한국 수출검역증으로 갈음되는지 조사 필요(Circular 25 는 입국만 다룸).
- **밀꾸 테스트 데이터** — 검수용으로 `destination` 에 `베트남` 을 추가해둔 상태
  (`일본, 필리핀, 베트남`). 확인 끝나면 되돌릴지 물어볼 것.
- **광견병 카드 파생 나머지** — 일본·EU 8곳·태국·필리핀은 아직 손 문구
  (대만·베트남·중국은 `buildRabiesCard()` 로 전환 완료).

### 4. 알아만 둘 것 (지금 문제 없음)
`tw.rabies-shipment-window` 에 **상한(1년)이 없다.** 지금은 대만이 `oneYearVaccineOnly`
라 유효기간이 자동 1년이고 `tw.rabies-not-expired-on-arrival` 이 대신 잡는다(접종 400일
뒤 출국 케이스로 확인). **다른 룰에 기대어 우연히 덮이는 구조**라, 유효기간 정책이 바뀌면
조용히 샌다.

## 오늘 한 것 (커밋 19개)

### 규정 오류 3건
- **항체 180일 오차단 해제** — 180일은 *격리 면제* 조건이지 입국 조건이 아니다.
  APHIA 원문: 「已滿 90 日但未滿 180 日 … 仍然是需要隔離檢疫 7 日的」. 90~180일은
  입국 가능 + 7일 격리인데 저장을 막고 있었다. 스냅샷의 **'정상 준비' 시나리오조차
  대만에서 차단**되던 상태였다.
- **수입허가 20일 리드타임** 입력불가 신설(양쪽 칸 모두 — 신청일·출발일).
- **광견병 선적 대기 룰** 신설(1차 90일 / 부스터 30일). 평소엔 항체 대기가 덮지만
  재검사 체인으로 대기가 면제되는 경로에서는 이 룰만 남는다.

### 기존 버그 4건
- 대만 수입허가 신청일에 입력불가가 통째로 빠져 있었다(태국·필리핀엔 있음).
- 귀국용 항체 목적지(태국·필리핀·베트남)에서 **저장이 통째로 거부**되고 있었다.
  가드는 있었지만 마지막 `validateTiterDate` 가 같은 규칙을 다시 적용해 무력화된 상태.
- 항체 목록 동기화 effect 가 `caseRow.data` 객체 정체성에 걸려 매 렌더마다 돌면서
  방금 추가한 빈 칸을 지웠다(버튼이 안 먹는 것처럼 보임).
- 출발일 입력칸이 없는 목적지에서 화면에 없는 stale 출발일로 '도착일이 출발일보다
  빨라요' 오차단. 고칠 입력칸조차 없었다.

### 문구 8건
2단계 마감 분리 / 일본 추가 검사 만료 과거형·없는 마감 제거 / 항체 만료 시제 분리 /
`N일 후` → `N일 후인` (5곳) / 항공권 안내문 90~180일 구간 명시 / 수입허가 120일 문구.

### 기능
- **추가 검사 카드 대만 확장** + 항체 유효기간 2년 하드코딩을 목적지별 선언 파생으로.
- **추가 검사 카드가 없는 목적지도 재검사 입력 가능** (본 카드가 목록을 통째로).
  예전엔 `rabies_titer_records[0]` 한 칸만 편집해 재검사가 이전 기록을 덮어썼다.
- **유효기간 만료 다음날 알림** 추가(공용 헬퍼 — 백신·종합·CIV·항체 전 목적지).

## 가드 현황 — 오늘 3개 층 넓혔다

```bash
pnpm lint:behavior            # 입력불가·주의·상황별 설명문·알림의 실제 반응
pnpm lint:validation-wiring   # 배선(남의 나라 룰/검증0개/고아 룰)
pnpm lint:dest                # 구조(카드·서류 구성)
pnpm lint:copy                # 목적지별 카드 문구
pnpm lint:checks              # 고객 노출 경고 문구
node scripts/lint-destination-scoping.mjs
```

**오늘 넓힌 것** — 이 층들이 없어서 오늘 고친 버그들이 안 보였다.
- 입력불가: 광견병 카드만 보던 것 → **수입허가 신청일·출국입국일** 추가
- **상황별 설명문(step.situational)** 층 신설 — 고객이 읽는 만료·진행중·재검사 안내가
  어떤 스냅샷에도 없었다(일본 문구를 고쳐도 5개 lint 가 그대로 통과했다)
- **시각 고정**을 주의 층까지 확대 — `cn`·`jp`·`th` 룰이 `todayKst()` 를 보고 있어
  스냅샷이 날마다 달라질 수 있었다. 고정하자 실제로 판정이 바뀌어 드리프트가 확인됨

**교훈**: 문구·룰을 고쳤는데 `lint:behavior` 가 조용히 통과하면 **그 케이스를 태우는
시나리오가 없다는 뜻**이다. 오늘 세 번 겪었다. 통과했다고 안심하지 말고 시나리오를 먼저 볼 것.

## 결정 기록 (다시 올리지 말 것)

전수 점검 때마다 "규정에 있는데 없다"로 걸리는 것들. **의도적**이다.

- **항체 수치 0.5 IU/mL 검증 안 함** / **마이크로칩 ISO 15자리 형식 검증 안 함**
  → `docs/destination-onboarding-checklist.md` §검증하지 않기로 한 것
- **검역에 완료 푸시 안 붙임** — 검역은 고객이 직접 간다. 푸시는 고객이 **결과를
  기다리는** 단계만(검사 결과·신고 수리·허가 발급).
  → `apps/portal/lib/journey/milestone-pushes.ts` 헤더
- **중국에 추가 검사 카드 안 붙임** — 유효기간(12개월)은 대만과 같지만 **대기기간이
  없어** 연장 개념이 없다. 만료돼도 아무 때나 다시 받아 나가면 된다.
  → `packages/domain/src/journey-steps/catalog.ts` rabies-titer-extra 주석

  완전히 망가져(뷰포트 0x0·스크린샷 타임아웃) **사용자 Chrome(claude-in-chrome)** 으로
  검증을 마쳤다.
- **JS 클릭은 이 앱 버튼에 안 먹는다**(포인터 이벤트). `computer` 도구의 실제 클릭을
  쓸 것. 합성 input 이벤트도 React 상태를 못 바꾼다 — 실제 타이핑 필요.
- Chrome 은 CSS 픽셀과 스크린샷 좌표의 **배율이 다르다**(1707 vs 1512). JS 로 좌표를
  구하면 `1512/window.innerWidth` 를 곱할 것.

## 반복해서 부딪히는 구조 문제

**프로파일 16개 필드 중 소비처가 있는 건 일부뿐이다.** `advanceNotice`·
`importQuarantine.quarantineDays`·`entryWaitAfterTiter` 등은 선언해도 아무 동작을 안 한다
(오늘 `entryWaitAfterTiter` 가 죽은 선언인 걸 확인했다 — 실제 숫자는 코드에 하드코딩).
그래서 새 목적지마다 카드·룰·알림·서류를 손으로 쓰게 되고 매번 뭔가 빠진다.

오늘 `TITER_ENTRY_VALIDITY_MONTHS`(카드 만료일)와 `TITER_EXTRA_CARD_DESTINATIONS`를
파생/단일출처로 옮겼다. 같은 방식으로 계속 옮기는 게 근본 해결. 옮길 때마다
**스냅샷 비교로 무동작 증명** 후 커밋할 것.
