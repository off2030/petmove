# 조직 연결 모델 리팩터 — 담당 동물병원 / 운송업체

> 단일 출처. 펫무브워크(admin) + 펫무브(portal) 공통. 2026-06-07 합의.

## 배경 (왜)

`cases.org_id` 하나가 ① 진입 조직(신청 발급처) ② 가시성/접근 ③ co_progress 형제 묶기
④ 삭제 권한을 **전부 겸함**. 여기에 어제(2026-06-08) `vet_org_id`를 새로 추가하면서
`org_id`와 역할이 **중복**됐고, "담당 병원을 바꾸면 이전 병원에서 빠진다"가 안 되는
충돌이 생김.

→ `org_id`를 **담당 동물병원**으로 명확히 하고, `vet_org_id`는 폐기. 가시성/소유를
고객이 고른 담당(병원+운송) 기준으로 통일. 동물 묶기(co_progress)는 보호자 기준으로 분리.

## 확정 모델

| 항목 | 결정 |
|---|---|
| `org_id` | **담당 동물병원** (변경 시 이동, 미정이면 platform `…0002`) |
| `transport_org_id` | **담당 운송업체** (유지) |
| `vet_org_id` | **제거** (어제 추가분 폐기) |
| 조직 테이블 | `organizations` + `org_type`(hospital/transport/both/platform) **그대로** — 운송 별도 테이블 X |
| 가시성(읽기·수정) | `org_id`(병원) + `transport_org_id`(운송) + 고객(case_customer_links) + 본사(super_admin) |
| 삭제 권한 | 병원 + 운송 둘 다 (v1 동일권한, 필드별 차등은 나중) |
| co_progress(함께 준비) | **보호자 단위 + 동시값만 연동** — 빈 칸 채움·동시 입력값은 연동, 각자/기존값은 독립(덮어쓰기·소실 방지) |
| 담당 = 고객 단위 | 한 보호자의 모든 동물이 같은 담당. 새 동물 등록 시 기존 담당 자동 연결 |
| 신청 연결 | org_type별 슬롯: hospital→`org_id`, transport→`transport_org_id`, both→둘 다, 직영→platform |
| 담당 병원 변경 | `org_id` 이동 + **snapshot**(본병원 접종→타병원 전환 + 약품 정보 복사 저장) |
| 마이크로칩 | **전역 unique** (`microchip` where deleted_at is null and microchip is not null) |
| 충돌 규칙 | 다른 병원 신청폼으로 새 동물 등록 = 기존 담당이 그 병원으로 **이동**(고객 전체) |
| 별지25 등 | 타병원 접종은 자동 제외 발급 (기존 룰 유지) — 새 병원이 체크 풀고 수정 가능 |

### 보존 보장 (중요)
- 케이스 **사실 데이터**(접종일·칩번호·항체검사일/수치·출국일 등)는 `case.data`에 저장 →
  담당/org 바뀌어도 **그대로**.
- 본병원 접종의 **약품 라벨**(제품명·제조사·로트)만 카탈로그 조회 의존이라, 담당 변경 시점에
  케이스로 **복사 저장(snapshot)** 해서 과거 기록을 굳힘.

## UI 카피 (확정)

- 담당 변경/해제 확인: **"현재 담당 동물병원이 더 이상 내 정보를 볼 수 없어요. 진행할까요?"**
- 미연결 권유: 내 정보의 기존 담당 병원 카드 placeholder → **"담당 동물병원을 연결해 보세요"**
  (새 카드 신설 X — 기존 `PartnerCard`가 그 역할)
