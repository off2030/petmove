# 일본 검역소 메일·승인·Form AC

권한과 공식 상태 원칙은 [실무 운영 기준](../../../../docs/work-management/operations.md)을 따른다. 이메일 조회는 연결된 Gmail, 작성·첨부·발송·검토 화면은 로그인된 Chrome Gmail을 사용한다.

## 메일 대조

- 업무 계정 lvmcfile@gmail.com의 일본 검역소(maff.go.jp)와 관련 NACCS 메일을 이전 확인보다 겹쳐 검색하고 페이지 끝까지 읽는다. 통상 개수로 제한하지 않는다. 실제 SENT와 후속 변경·취소까지 대조한다.
- 보호자·동물·칩·신고번호·여행일·공항을 Work 현재 여행에 연결한다. 현재 본문 요구를 항목별로 추리고 인용된 과거 문구·다른 동물/여행과 구분한다. 승인 메일의 EXPORT 항목도 읽는다.
- 자료를 보낸 것과 기관 승인·예약 확정은 다르다. 한 메일의 여러 동물은 모두 확인한다. 이미 사용자가 회신했으면 다시 미처리 요청으로 보고하지 않는다.
- 지원되지 않는 새 요청·최종 정부 확인본·미수령 고객 사진·모호한 대상/일정은 동물/보호자·검역소·메일 시각·현재 요구·막힌 이유·필요 자료/판단·기한을 보고한다. 변화 없는 대기라고 숨기거나 임의 답장하지 않는다.
- 허용된 답장은 영어로 원래 제목의 현재 여행 스레드에 쓴다. 요구한 접종증명서·가방 사진 등 모든 항목과 첨부 완료를 확인한다. 새 사실·일정·실제 진찰을 약속하지 않는다.

## 수입 승인과 승인서

현재 여행의 명확한 승인 본문을 확인하면 기존 Work 수입 완료 액션으로 반영·재조회한다. 자동 등록/접수 알림·보완 요청은 승인이 아니다. 승인서 원본은 내려받아 보호자·동물·칩번호·신고번호·입국일을 대조한 뒤 해당 여행에 첨부·재조회하고 원본 바이트/해시를 대조한다. 기존 첨부/다른 여행/수출을 보존하고 동일 파일은 중복 첨부하지 않는다.

승인 메일과 NACCS 상태가 다르거나 출력·다운로드·로그인·첨부가 막히면 수입 완료를 되돌리지 않는다. 양쪽 근거와 파일 미보관 사유·재개 위치를 후속 할 일로 유지한다. 빈 양식이나 새 PDF로 승인서를 대체하지 않는다.

## 수출 예약 확정

- 등록 알림·희망 일시·가능 시간 제안은 확정이 아니다. 확정 날짜·시간을 해당 Work 희망 일시와 대조하고 모두 일치하면 수출 완료·재조회한다.
- 특정 입국일의 입국검사 후/직후 수출검사를 진행한다는 명확한 안내도 대상 여행·입국일·예약일 일치 시 완료 근거다. 별도 시각이 없다고 보류하지 않으며 저장 시각을 임의 수정하거나 그 시각까지 확정됐다고 쓰지 않는다.
- 날짜·명시된 시각 불일치, 예약 불가·조건부 검토·불명확한 대상은 완료 처리하지 않는다. 요청값·회신값·사유·대안을 보고하고 일정 수정/답장은 별도 지시를 따른다.

## Form AC 사전 검토본

현재 여행의 명시적인 사전 검토 요청이 있으면 준비·답장한다. 별도 요청이 없어도 출국 21일 전, 이미 기한 이내인 미발송 여행은 출국 전 첫 정상 점검에서 수행한다. 전체 페이지·모든 일본 여행 토큰을 확인하고 취소·출국 완료·날짜 불명확 건은 제외한다. 일반적인 사전 검토 권고와 명시적 조기 요청은 구분한다.

1. 실제 SENT의 대상·여행·신고번호·첨부와 공유 이력을 대조한다. 사용자 수동 발송도 기발송이다. 이미 발송한 여행을 기한만으로 다시 보내지 않는다. 수정/재송부 요구는 현재 본문과 직전 발신으로 판정한다.
2. 기존 `generateFormAC(caseId,{destination:현재 일본 여행 토큰,includeVet:true,includeSignature:false})`를 직접 실행한다. 실제 기관·케이스·여행 자료와 기존 서식/전처리를 유지하고 원본 DB를 바꾸지 않는다. 수의사·등록 내원 예정일은 유지하고 서명만 제외한다.
3. 출력 전후 보호자·한국/일본 주소, 동물명·종·품종·성별·DOB/확인 나이·모색, 칩·식별일, 필요한 접종일·유효기간·제품/제조사, 항체 채혈일·결과·기관, 수의사와 내원일을 대조한다. 필수값 누락/불일치나 오늘 날짜로의 조용한 대체는 임의 보충·발송하지 않고 보고한다. 빈 추가 접종/검사행·서명·정부 확인란은 정상 초안 빈칸이다.
4. 예정 진찰일은 이메일에 예정이라고 밝히며 진찰·정부 확인 완료로 쓰지 않는다. 검토본임을 알 수 있는 영문 파일명을 사용한다. 최종본·고객 사진과 구분한다.
5. 발송 직전 실제 SENT와 원격 최신 이력을 다시 읽는다. 충돌·다른 실행 처리 중·공유 연결 실패면 발송을 중단하고 보고한다. 원래 제목으로 현재 검역소 스레드에 회신하며 모든 PDF 첨부 완료를 확인한다.
6. 발송 후 수신자·여행·스레드·신고번호·첨부가 일치하는 SENT를 재조회하고 메시지 ID·발송일·첨부와 남은 행동을 같은 비공개 공유 원본에 병합·저장·재조회한다. 발송이 불명확하면 반복 전송 전에 SENT부터 확인한다.

Form AC 발신·검토 통과는 Work 검사/수입/수출·최종 서류 준비 완료의 근거가 아니다. 검역 후 고객 사진을 받아 최종본을 전달하는 건은 실제 수령 전 자료 대기다. 매일 점검의 필수 보고/완료 검증은 정기 점검 스킬을 따른다.
