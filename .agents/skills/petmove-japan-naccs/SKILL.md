# 펫무브 일본 NACCS 신고

반려견·반려묘의 일본 여행 신고와 검역소 이메일 업무를 진행한다. 데이터 조회·증명서 생성은 직접 도구를 기본으로 하고 NACCS 조작·이메일 작성과 첨부·발송·사용자의 화면 확인은 Chrome에서 진행한다. 사용자가 같이 보자고 하면 지정한 화면까지만 이동하고 기다린다. 자동 진행을 요청하면 확인된 자료로 진행하되, '신청 전까지'라면 Notification/Apply를 누르지 않는다. 스킬 호출 자체는 새 신고의 제출 허가가 아니다. 현재 대화의 제출 지시와 범위를 따른다.

## 자료 및 공통 기준

- 조회·대조·PDF 필수값 판정 전에 [실무 지침의 조회값 해석 기준](../../../docs/work-management/operations.md#조회값은-화면pdf의-실제-선택-규칙으로-해석)을 적용한다. 원시 컬럼이나 조회 요약이 화면·PDF와 다르면 현재 구현의 우선 필드·대상 여행지·폴백을 재확인한 뒤 판단한다. 정상 분리 필드가 있는데 과거 합본값만 보고 불일치로 판단하는 일을 반복하지 않는다.
- 펫무브워크의 대상 보호자·동물·일본 여행·신고 상태를 구성된 읽기 전용 데이터 조회로 확인한다. 화면이 필요하면 `https://work.petmove.co.kr/cases`의 **신고 탭**을 사용한다. 이전에 열린 케이스를 그대로 믿지 않는다. 같은 보호자의 동물이 여러 마리면 함께 신고할 대상인지 확인하고 모두 입력한다.
- 보호자 영문명은 화면·PDF와 동일하게 `data.customer_first_name_en`/`data.customer_last_name_en`을 우선 사용하고, 분리 필드가 없을 때만 이전 합본 컬럼 `customer_name_en`을 폴백으로 사용한다. 분리 필드가 정상인데 합본 컬럼에 과거 값이 남았다는 이유로 불일치·발송 보류로 보고하지 않는다. 내원일 등은 해당 여행지의 `by_dest` 우선값을 확인한다.
- 이름, 칩번호, 생년월일, 성별, 품종, 색, 체중, 칩 삽입일, 접종일/유효기간, 항체 채혈일/결과/기관, 왕복 항공편, 한국·일본 주소와 보호자 연락처를 대조한다. 부족한 자료는 지어내지 않는다.
- 첨부는 파일명만으로 판단하지 말고 내용을 열어 이름·칩번호를 대조한다. 항체결과지와 잘 나온 이동가방 전체 사진 **한 장**을 선택한다.
- 신청자 이름은 `JINWON LEE AND {보호자 영문명}`으로 대문자를 통일한다. 이메일 기본값은 **lvmcfile@gmail.com**. 보호자 현지 연락수단에는 보호자 전화·이메일을 사용한다. 예전 petmove@naver.com 지시는 이 이메일로 정정되었다.
- 길이·높이는 사용자의 업무 관례에 따라 품종·체중에서 추정하여 **5cm 단위**로 입력한다. 실측이 있으면 실측 우선. 예: 약 5kg 포메라니안 길이35/높이30cm. 체중은 실제 기록값이다.
- 칩 위치 **NECK**, 제조사 **OTHER**, 규격 **ISO**는 사용자가 정한 기본값이다. 실제 증빙과 충돌하면 확인한다.
- 접종은 **최신 먼저**, 종류 **INACTIVATED**, 제품/제조사는 `Rabisin/Boehringer Ingelheim` 형식. 기록에 다른 제품이 명시되면 임의로 바꾸지 않는다. 유효기간은 해당 기록을 따른다.
- 항체검사는 최신 먼저. 결과지의 수치가 0.5 이상이면 `0.5IU/ml or over`. APQA 서울 검사기관 코드 KR01은 **결과지 기관·주소가 일치할 때만** 사용한다. 채혈일과 접수일·발급일을 혼동하지 않는다.
- 이 기준은 사용자 업무 관례이며 법적 입국 요건 전체가 아니다. 요건·정책 판단이 필요하면 당시 공식 AQS 자료를 확인한다.

## 증명서 출력 및 이메일 답장

- 증명서는 브라우저를 열지 않고 펫무브워크의 기존 PDF 생성 함수를 직접 실행하는 방식을 기본으로 한다. 실제 케이스·소속 기관의 데이터를 읽기 전용으로 조회하고 기존 서식·접종 필터·제품 정보·서명·수의사 처리 로직을 그대로 사용한다. 별도 서식을 재작성하거나 출력 때문에 원본 데이터를 변경하지 않는다. 구체적인 접종증명서 준비는 [수입 절차](references/import.md)를 따른다.
- 화면 작업은 자동 로그인된 **Chrome**을 사용하며 인앱 브라우저로 대체하지 않는다. 이메일 조회·기록에는 연결 도구를 사용할 수 있지만 답장 작성·첨부·발송과 사용자의 검토 화면은 Chrome Gmail에서 진행한다. 사용자가 볼 수 있게 실제 답장 본문과 첨부파일이 표시된 탭을 열어두고 확인한다. 초안 준비와 발송을 구분하고 사용자가 요청한 단계까지만 진행한다.
- 검역소 답장은 기본적으로 영어로 작성하고 원래 제목을 유지한다. 현재 메일 본문의 요구사항을 항목별로 추려, 각 항목에 답변 내용과 필요한 첨부파일이 갖춰졌는지 대조한다. 접종증명서 준비에 집중하다 이동가방 사진 등 다른 요구를 누락하지 않는다. 여러 동물의 자료는 각각 확인하며, 같은 사진이 등록돼 있다는 이유만으로 실제 같은 제품을 쓴다고 단정하지 않는다. 확인되지 않은 요구사항은 사용자에게 명시하고, 발송 전 첨부 완료까지 확인한다.

### Form AC 사전 검토본

- 기존 `generateFormAC(caseId, { destination: '일본', includeVet: true, includeSignature: false })`를 사용한다. 현재 케이스·일본 여행·소속 기관의 정보를 그대로 출력하고 **수의사 서명만 제외**한다. 초안이라는 이유로 수의사 정보나 등록된 내원 예정일을 임의로 비우지 않는다. 실제 진찰 전 날짜는 이메일에서 예정일임을 설명하며 진찰·정부 확인이 완료됐다고 쓰지 않는다. 기존 PDF 서식·전처리를 유지하고 원본 DB는 바꾸지 않는다.
- 출력 전 필수 정보와 출력 후 PDF의 실제 값을 대조한다. 보호자 영문명·한국/일본 주소, 동물명·종·품종·성별·생년월일 또는 확인된 나이·모색, 칩번호·식별일, 필요한 광견병 접종일·면역유효기간·제품/제조사, 항체 채혈일·결과·검사기관, 수의사명·주소·등록된 내원일을 확인한다. 발송 대상 검역소·신고번호·출국/입국일·편명도 현재 여행과 대조한다. **필수값 누락·불일치나 오늘 날짜 등으로의 조용한 자동 대체가 있으면 임의로 채우거나 발송하지 말고 해당 항목을 보고한다.** 사용하지 않는 추가 접종/검사 행, 초안의 수의사 서명 및 정부 검역관 서명·직인란은 정상적인 빈칸으로 구분한다.
- 검토본임을 알 수 있는 영문 파일명으로 첨부하고 영어로 사전 검토를 요청한다. 기존 검역소 메일이 있으면 같은 제목의 원문에 답장한다. 별도의 긴 해설이나 새로운 서식을 만들지 않는다. 이미 검증한 생성 경로를 재사용하고 대상 자료·출력·첨부·발송 결과 확인에 집중한다. 최종 정부 확인본이나 고객 사진은 사전 검토본과 구분한다.

## 절차 선택

- 일본 입국: [수입 절차](references/import.md)를 읽는다.
- 귀국편 일본 출국: [수출 절차](references/export.md)를 읽는다. **사용자가 해당 여행의 신고 진행·제출을 요청했고 왕복 일정과 귀국편이 등록돼 있으면, 수입 사전신고·수입검사 신청 후 귀국편 수출검역 신청까지 같은 작업에서 이어서 제출한다.** 요청에 ‘수입신고’라고만 쓰였다는 이유로 수출을 빠뜨리거나 재승인을 요구하지 않는다. 사용자가 ‘수입만’, ‘수출은 나중에’, ‘제출 전까지’처럼 명시적으로 제한하면 그 범위를 우선한다. 귀국편·희망 검역 일시가 비거나 모순되면 해당 항목만 확인하고 임의로 보충하지 않는다. 정기 조회·보고만 하는 실행에 새 신고 제출 권한을 부여하는 규칙은 아니다. **NACCS 메뉴 탭을 닫지 않는다.**
- 신고 변경: [수정 및 브라우저 주의사항](references/operations.md)을 읽는다. 브라우저 오류에도 이 문서를 참고한다.

완료는 실제 Application Completed 화면과 신청번호로 확인한다. 등록 완료(Notification)와 검사 신청 완료(Apply)는 다르다. 신청 접수와 검역소 승인·예약 확정도 구분해 보고한다.

왕복 신고 작업을 마치기 전에 대상 여행의 수입·수출 각각에 대해 기존 유효 신청 또는 이번 Application Completed와 신청번호를 대조하고, 제출한 두 슬롯의 펫무브워크 저장값을 재조회한다. 수출까지 제출하지 못했으면 빠진 단계·이유·재개 위치를 남기고 작업 전체를 완료로 보고하지 않는다. 등록된 희망 시간은 예약 요청에 사용하며, 검역소의 확정 회신 전에는 확정으로 표현하거나 수출 상태를 `완료`로 바꾸지 않는다.

## 신청 후 펫무브워크 상태 반영

NACCS 신청 완료를 확인한 뒤, 펫무브워크 신고 탭에서 **해당 보호자·동물·일본 여행의 해당 수입/수출 상태를 `진행`으로 변경**하는 것까지 업무에 포함한다. 수입만 신청했으면 수입만, 수출까지 신청했으면 수출도 변경한다. 수정 신청을 마친 경우 이미 진행이면 유지한다. 신청 전 검토·임시저장·오류로 미제출 상태에서는 변경하지 않는다.

`진행`은 신청 제출 후 검역소 처리 대기 상태다. NACCS 제출 완료만으로 펫무브워크를 `완료`로 바꾸지 않는다. 기존 `완료` 상태를 임의로 진행으로 낮추지 않는다. 승인 확인에 따른 완료 전환은 해당 확인 또는 사용자의 별도 지시가 있어야 한다.

## 이메일로 수입·수출 완료 판정

- 펫무브워크 데이터를 직접 조회하고 `lvmcfile@gmail.com`의 일본 검역소 메일을 최근부터 검토한다. 보호자·동물·신청번호·목적지·왕복 일정으로 해당 여행을 대조한다. 메일 제목이나 인용된 과거 승인 문구만으로 판단하지 않고 현재 본문과 후속 변경·취소 여부를 확인한다. 한 메일이 여러 동물을 다루면 적용 대상 모두를 확인한다.
- 수입 상태는 해당 여행의 수입허가·신고 승인 또는 승인서 발급이 명확히 확인되면 `완료`로 처리한다. NACCS 등록 알림, 접수 확인, 보완 요청은 승인으로 간주하지 않는다. 사용자는 2026-10-23에 로잔동물의료센터의 수입 승인 확인 후 승인서 다운로드·해당 일본 여행의 펫무브워크 첨부·수입 완료 반영·재조회를 매번 별도 지시 없이 수행하도록 위임했다. 승인서의 보호자·동물·칩번호·신고번호·입국일을 현재 여행과 대조하고 기존 첨부·다른 여행·수출 상태를 보존한다. 동일 승인서가 이미 첨부되어 있으면 중복 업로드하지 않는다. 저장된 첨부와 수입 완료를 재조회한 뒤 실행 결과와 남은 일을 함께 보고한다. 로그인·CAPTCHA·다운로드/첨부 오류로 실행이 막히면 구체적인 중단 지점과 미반영 상태를 보고한다.
- 귀국 데이터가 있는 동물의 일본 수출신고는 별도 허가증 발급을 기다리는 업무가 아니다. 검역소 메일에서 해당 동물·여행의 수출검사 **예약 확정**이 확인되면 수출 상태를 `완료`로 처리한다. 예약 확정 일시를 확인하며, 신청 등록·희망 시간·가능한 시간 제안·회신 대기는 확정으로 간주하지 않는다. 수입 승인만으로 수출도 완료 처리하거나 수출 예약만으로 수입도 완료 처리하지 않는다.
- 예약 확정 메일의 날짜·시간을 해당 일본 여행의 펫무브워크 수출검역 예약 일시와 대조한다. **명시된 날짜·시간이 모두 일치하면 바로 수출 상태를 완료 처리하고 재조회한다.** 2026-10-23 사용자 위임에 따라 검역소가 해당 동물·여행에 대해 **특정 입국일의 입국검사 완료 후/직후 수출검사를 진행한다고 명확히 안내한 경우도 예약 확정 근거로 인정한다.** 이 경우 입국일과 수출검역 예약일이 그 날짜와 일치하는지 대조하고, 별도 시각이 없다는 이유만으로 보류하지 않는다. 예: “On December 17, we plan to conduct an export inspection after the import inspection is completed.”는 날짜와 검사 순서가 정해진 안내다. 이때 저장된 시각을 메일이 확인했다고 쓰거나 임의의 시각으로 환산·수정하지 않고 기존 예약 일시를 보존한다. 단순 가능성·시간 제안·조건부 검토는 확정으로 취급하지 않는다. 날짜 불일치·명시된 시각 불일치·필요한 기록 누락·불명확한 대상은 예약 일시와 상태를 변경하지 않고 양쪽 근거와 차이를 보고한다. 사용자가 일시 수정·완료 처리를 지시하면 그 범위만 따른다. 이 완료 처리는 위임 범위이며, 별도로 조회·보고만 하도록 제한한 실행에서는 그 제한을 우선한다.
- 수출검사 예약을 해줄 수 없다는 회신은 완료 처리하지 않는다. 요청 일시·검역소가 제시한 불가 사유·가능한 대체 일시/장소·사용자 답변 필요 여부를 본문에서 확인해 사용자에게 전달한다. 불가 회신에 대체 시간이 제안돼 있어도 사용자 수락이나 검역소의 명확한 예약 확정 전에는 완료로 판단하지 않는다. 메일 답장이나 일정 변경을 임의로 실행하지 않는다. 이 판정은 매일 이메일 확인 작업에도 적용한다.
- 이미 완료인 해당 상태는 유지한다. 매일 확인·완료 반영을 위임받은 경우 확실히 일치하는 진행 건의 해당 수입/수출 상태만 변경하고 저장 결과를 재조회한다. 대상 또는 확정 여부가 모호하면 변경하지 않고 근거와 확인할 사항을 보고한다. 이번 요청이 이해·대조·검토만이면 상태를 변경하지 않는다. 메일 답장·자료 제출·일정 변경은 별도 요청 범위에 따른다.

신고 목록의 수입/수출 열을 확인하고 상태 메뉴에서 진행을 선택한다. 같은 이름이 다른 보호자명에 포함될 수 있으므로 보호자와 동물을 함께 식별한다. 화면 저장이 잠시 지연될 수 있으므로 선택 직후 이전 값이 보인다고 반복 클릭하지 말고, 해당 행의 최종 상태가 진행인지 확인한다. 결과 보고에는 신청번호와 변경한 상태를 함께 적는다.

## 매일 이메일 확인 및 예외 보고

- **신고 탭 대기·진행 여행은 새 메일 유무와 관계없이 계속 확인한다.** [세 탭 점검의 신고 후속 확인 기준](../petmove-inspection-check/references/daily-three-tabs.md#신고)에 따라 현재 Work 수입/수출 슬롯과 기존 미완료 할 일을 대조한다. 수입만 끝났거나 승인 통지 후 승인서 첨부·저장 반영이 남았거나 수출 예약이 미확정이면 추적을 끝내지 않는다. 일반적인 새 신고 제출·답장 권한은 확대하지 않고 위임된 실행만 수행한다.
- 사용자는 2026-10-23에 Form AC 초안 발송 시험을 확인하고 **사전 검토본의 자동 준비·첨부·답장·실제 발송을 위임**했다. 로잔동물의료센터의 현재 일본 여행을 대상으로, 검역소가 현재 본문에서 Form AC 사전 검토본을 요청하면 기존 정기 점검 때 준비해 답장한다. 별도 요청이 없어도 **한국 출국일 21일 전(3주 전)**의 오후 1시 점검에서 발송한다. 기한이 지난 미발송 건은 출국 전 첫 정상 점검에서 같은 기준으로 처리한다. 취소·출국 완료·다른 조직의 여행은 제외하고 출국일이 없거나 모호하면 추정하지 않는다. 이는 사용자의 업무 시점 기준이며 법정 기한이 아니다. 정기 점검 사이의 즉시 실시간 회신을 보장하지 않는다.
- 위임 범위는 검증 가능한 Form AC 사전 검토본의 발송과 해당 자료에 대한 정형 회신이다. 수신 메일이 있다는 이유만으로 새로운 일정·사실을 약속하거나 최종 정부 확인본·미수령 고객 사진·새로운 서류를 만들어 보내지 않는다. 정형 절차로 처리할 수 없는 요구·자료 누락·대상 불일치는 보고한다. 승인메일의 일반적인 사전 검토 권고는 별도 조기 제출 요구와 구분하고, 명시적 요청이 없으면 21일 전 기준을 따른다.
- Form AC를 보냈다는 판정은 해당 보호자·동물·여행 일정·신고번호와 일치하는 실제 발신 메일 및 첨부를 근거로 한다. 동명이 다른 동물이나 과거 여행의 발신 내역을 섞지 않는다. 검역소가 보낸 빈 양식·샘플 첨부, 펫무브워크의 서류 준비 완료, 초안 저장을 발송으로 간주하지 않는다. 초안 사전 검토·검역소의 검토 회신·정부 검역 후 최종 증명서 전달을 구분한다. 확인만 요청받았으면 발송·초안 저장·상태 변경을 하지 않는다.
- 매 점검에서 수신 메일뿐 아니라 아직 출국 전인 일본 여행의 출국일까지 남은 날짜와 실제 Form AC 발신 내역도 직접 조회한다. 사용자 수동 발송도 포함해 이미 발송된 여행은 기한 도래만으로 재발송하지 않는다. 새 수정·재송부 요구는 현재 본문과 앞선 발신 내용으로 필요성을 확인한다. 발송 직전에 공유 이력과 보낸편지함을 다시 확인해 기기 간 중복을 막고, 다른 실행의 처리 중 표시나 동기화 실패·충돌이 있으면 자동 발송을 멈추고 보고한다. 발송 결과가 불명확하면 재전송하지 말고 보낸편지함에서 먼저 확인한다.
- 실제 발송 후 수신자·원문 스레드·동물/여행/신고번호·첨부가 일치하는 보낸편지함 메일을 재조회하고 메시지 ID·발송일·첨부 식별 정보를 비공개 공유 이력에 남긴다. Form AC 발송을 검사·수입/수출신고 완료로 바꾸지 않는다. 성공 또는 발송을 막은 문제를 간결히 알린다.
- 현재 정기 작업은 한국 시간 매일 오후 1시에 시작한다. 이전 확인 이후의 일본 검역소·관련 NACCS 메일을 모두 확인한다. 통상 하루 1~3개여도 개수로 제한하지 않는다. 검색 기간을 조금 겹치고 메시지 ID로 중복 제거하며, 결과가 많으면 페이지를 이어 확인한다. 미검토 메일을 건너뛰어 확인 시점을 앞당기지 않는다.
- 발신 답장과 후속 회신까지 확인해 이미 보낸 자료를 다시 미발송으로 보고하지 않는다. 보완자료 발송 완료와 검역소 승인·예약 확정은 구분한다. 수입 승인 메일의 EXPORT 항목에도 수출 예약 확정이 있을 수 있으므로 본문 전체를 읽는다.
- 자동화는 조회·할 일 보고에 더해 위에서 위임된 Form AC 사전 검토본 준비·첨부·발송과 확정된 수출 예약 일치 시 완료 처리를 수행한다. 수입 승인 확인 시 위에서 위임된 승인서 다운로드·펫무브워크 첨부·수입 완료 반영·재조회도 자동 수행한다. 그 밖의 이메일 발송·자료 업로드·예약 일시 변경·새 신고 제출은 별도 지시를 따른다. NACCS 로그인 CAPTCHA는 해당 시점에 사용자 승인을 받는다. 확인만 보고하지 말고 권한 안에서 실행한 결과와 미실행 사유를 함께 보고한다.
- **설명된 절차로 처리할 수 없거나 판단이 애매한 새 이메일은 반드시 사용자에게 보고한다.** 동물/보호자, 검역소·메일 시각, 현재 요구사항, 처리할 수 없는 이유, 필요한 자료·사용자 판단·기한을 정리한다. 제목·본문의 대상 불일치, 증빙 누락, 새로운 요청, 예약 충돌을 임의로 해석해 답장·제출·완료 처리하지 않는다.
- Form AC 초안에 문제가 없다는 회신과 최종본 재송부 요청을 구분한다. 사용자가 고객의 검역소 검역 후 카카오톡 사진을 받아 전달한다고 설명한 건은 고객 자료 대기로 기록하며, 사진이 오기 전 즉시 재송부할 일로 보고하지 않는다. 실제 받은 사진의 대상·서류 내용을 확인한 뒤 사용자 지시 범위에서 전달한다.
- 확인 이력과 미완료 상태는 Git에서 제외된 로컬 업무 기록에 남긴다. 처리 필요, 고객 자료 대기, 검역소 회신 대기를 구분한다. 새 조치·예외·승인·예약 확정·오류 등 의미 있는 변화는 알리고, 변화 없는 대기는 중복 알림하지 않는다. 자동 처리 불가능한 새 요청을 단순 대기로 분류해 알림을 생략하지 않는다.
- 업무 PC와 노트북의 정기·수동 점검은 [기기별 점검 인계](../../../docs/laptop-daily-check-handoff.md)의 Google Drive 비공개 이력을 공통 원본으로 사용한다. 시작 전에 최신 이력을 읽고, 종료 시 다른 기기의 갱신을 대조·병합해 동일 원격 파일 ID로 저장한 뒤 재조회한다. 실제 고객 이력·메일 ID·비밀키는 Git에 넣지 않는다. 연결 실패나 충돌 시 동기화 완료로 간주하지 않고 로컬 결과를 보존해 보고한다.

고객 케이스의 개인정보나 과거 신청번호를 스킬에 고정하지 않는다.
