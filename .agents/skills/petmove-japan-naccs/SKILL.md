# 펫무브 일본 NACCS 신고

반려견·반려묘의 일본 여행 신고와 검역소 이메일 업무를 진행한다. 데이터 조회·증명서 생성·이메일은 직접 도구를 기본으로 하고 NACCS 조작이나 사용자가 화면 확인을 요청한 단계는 Chrome에서 진행한다. 사용자가 같이 보자고 하면 지정한 화면까지만 이동하고 기다린다. 자동 진행을 요청하면 확인된 자료로 진행하되, '신청 전까지'라면 Notification/Apply를 누르지 않는다. 스킬 호출 자체는 새 신고의 제출 허가가 아니다. 현재 대화의 제출 지시와 범위를 따른다.

## 자료 및 공통 기준

- 펫무브워크의 대상 보호자·동물·일본 여행·신고 상태를 구성된 읽기 전용 데이터 조회로 확인한다. 화면이 필요하면 `https://work.petmove.co.kr/cases`의 **신고 탭**을 사용한다. 이전에 열린 케이스를 그대로 믿지 않는다. 같은 보호자의 동물이 여러 마리면 함께 신고할 대상인지 확인하고 모두 입력한다.
- 이름, 칩번호, 생년월일, 성별, 품종, 색, 체중, 칩 삽입일, 접종일/유효기간, 항체 채혈일/결과/기관, 왕복 항공편, 한국·일본 주소와 보호자 연락처를 대조한다. 부족한 자료는 지어내지 않는다.
- 첨부는 파일명만으로 판단하지 말고 내용을 열어 이름·칩번호를 대조한다. 항체결과지와 잘 나온 이동가방 전체 사진 **한 장**을 선택한다.
- 신청자 이름은 `JINWON LEE AND {보호자 영문명}`으로 대문자를 통일한다. 이메일 기본값은 **lvmcfile@gmail.com**. 보호자 현지 연락수단에는 보호자 전화·이메일을 사용한다. 예전 petmove@naver.com 지시는 이 이메일로 정정되었다.
- 길이·높이는 사용자의 업무 관례에 따라 품종·체중에서 추정하여 **5cm 단위**로 입력한다. 실측이 있으면 실측 우선. 예: 약 5kg 포메라니안 길이35/높이30cm. 체중은 실제 기록값이다.
- 칩 위치 **NECK**, 제조사 **OTHER**, 규격 **ISO**는 사용자가 정한 기본값이다. 실제 증빙과 충돌하면 확인한다.
- 접종은 **최신 먼저**, 종류 **INACTIVATED**, 제품/제조사는 `Rabisin/Boehringer Ingelheim` 형식. 기록에 다른 제품이 명시되면 임의로 바꾸지 않는다. 유효기간은 해당 기록을 따른다.
- 항체검사는 최신 먼저. 결과지의 수치가 0.5 이상이면 `0.5IU/ml or over`. APQA 서울 검사기관 코드 KR01은 **결과지 기관·주소가 일치할 때만** 사용한다. 채혈일과 접수일·발급일을 혼동하지 않는다.
- 이 기준은 사용자 업무 관례이며 법적 입국 요건 전체가 아니다. 요건·정책 판단이 필요하면 당시 공식 AQS 자료를 확인한다.

## 증명서 출력 및 이메일 답장

- 증명서는 브라우저를 열지 않고 펫무브워크의 기존 PDF 생성 함수를 직접 실행하는 방식을 기본으로 한다. 실제 케이스·소속 기관의 데이터를 읽기 전용으로 조회하고 기존 서식·접종 필터·제품 정보·서명·수의사 처리 로직을 그대로 사용한다. 별도 서식을 재작성하거나 출력 때문에 원본 데이터를 변경하지 않는다. 구체적인 접종증명서 준비는 [수입 절차](references/import.md)를 따른다.
- 이메일 답장도 연결된 Gmail 도구로 원문에 이어 작성·첨부하는 것이 기본이다. 사용자가 화면을 보며 진행하길 원하면 브라우저에서 준비한다. 초안 준비와 발송을 구분하고 사용자가 요청한 단계까지만 진행한다.
- 검역소 답장은 기본적으로 영어로 작성하고 원래 제목을 유지한다. 현재 메일 본문의 요구사항을 항목별로 추려, 각 항목에 답변 내용과 필요한 첨부파일이 갖춰졌는지 대조한다. 접종증명서 준비에 집중하다 이동가방 사진 등 다른 요구를 누락하지 않는다. 여러 동물의 자료는 각각 확인하며, 같은 사진이 등록돼 있다는 이유만으로 실제 같은 제품을 쓴다고 단정하지 않는다. 확인되지 않은 요구사항은 사용자에게 명시하고, 발송 전 첨부 완료까지 확인한다.

## 절차 선택

- 일본 입국: [수입 절차](references/import.md)를 읽는다.
- 귀국편 일본 출국: [수출 절차](references/export.md)를 읽는다. 수입 신청 후 귀국편이 있으면 이어서 진행할 필요를 확인한다. **NACCS 메뉴 탭을 닫지 않는다.**
- 신고 변경: [수정 및 브라우저 주의사항](references/operations.md)을 읽는다. 브라우저 오류에도 이 문서를 참고한다.

완료는 실제 Application Completed 화면과 신청번호로 확인한다. 등록 완료(Notification)와 검사 신청 완료(Apply)는 다르다. 신청 접수와 검역소 승인·예약 확정도 구분해 보고한다.

## 신청 후 펫무브워크 상태 반영

NACCS 신청 완료를 확인한 뒤, 펫무브워크 신고 탭에서 **해당 보호자·동물·일본 여행의 해당 수입/수출 상태를 `진행`으로 변경**하는 것까지 업무에 포함한다. 수입만 신청했으면 수입만, 수출까지 신청했으면 수출도 변경한다. 수정 신청을 마친 경우 이미 진행이면 유지한다. 신청 전 검토·임시저장·오류로 미제출 상태에서는 변경하지 않는다.

`진행`은 신청 제출 후 검역소 처리 대기 상태다. NACCS 제출 완료만으로 펫무브워크를 `완료`로 바꾸지 않는다. 기존 `완료` 상태를 임의로 진행으로 낮추지 않는다. 승인 확인에 따른 완료 전환은 해당 확인 또는 사용자의 별도 지시가 있어야 한다.

## 이메일로 수입·수출 완료 판정

- 펫무브워크 데이터를 직접 조회하고 `lvmcfile@gmail.com`의 일본 검역소 메일을 최근부터 검토한다. 보호자·동물·신청번호·목적지·왕복 일정으로 해당 여행을 대조한다. 메일 제목이나 인용된 과거 승인 문구만으로 판단하지 않고 현재 본문과 후속 변경·취소 여부를 확인한다. 한 메일이 여러 동물을 다루면 적용 대상 모두를 확인한다.
- 수입 상태는 해당 여행의 수입허가·신고 승인 또는 승인서 발급이 명확히 확인되면 `완료`로 처리한다. NACCS 등록 알림, 접수 확인, 보완 요청은 승인으로 간주하지 않는다.
- 귀국 데이터가 있는 동물의 일본 수출신고는 별도 허가증 발급을 기다리는 업무가 아니다. 검역소 메일에서 해당 동물·여행의 수출검사 **예약 확정**이 확인되면 수출 상태를 `완료`로 처리한다. 예약 확정 일시를 확인하며, 신청 등록·희망 시간·가능한 시간 제안·회신 대기는 확정으로 간주하지 않는다. 수입 승인만으로 수출도 완료 처리하거나 수출 예약만으로 수입도 완료 처리하지 않는다.
- 예약 확정 메일의 날짜·시간을 해당 일본 여행의 펫무브워크 수출검역 예약 일시와 대조한다. **둘이 일치하면 바로 수출 상태를 완료 처리하고 재조회한다. 다르거나 기록이 없으면 예약 일시와 상태를 변경하지 않고 양쪽 값과 차이를 사용자에게 보고한다.** 사용자가 확정 일시로 수정·완료 처리를 지시한 경우에만 그 지시에 따라 수정한다. 단순 시간 제안을 확정으로 취급하지 않는다. 이 일치 시 완료 처리는 사용자가 위임한 범위이며, 별도로 조회·보고만 하도록 제한한 실행에서는 그 제한을 우선한다.
- 수출검사 예약을 해줄 수 없다는 회신은 완료 처리하지 않는다. 요청 일시·검역소가 제시한 불가 사유·가능한 대체 일시/장소·사용자 답변 필요 여부를 본문에서 확인해 사용자에게 전달한다. 불가 회신에 대체 시간이 제안돼 있어도 사용자 수락이나 검역소의 명확한 예약 확정 전에는 완료로 판단하지 않는다. 메일 답장이나 일정 변경을 임의로 실행하지 않는다. 이 판정은 매일 이메일 확인 작업에도 적용한다.
- 이미 완료인 해당 상태는 유지한다. 매일 확인·완료 반영을 위임받은 경우 확실히 일치하는 진행 건의 해당 수입/수출 상태만 변경하고 저장 결과를 재조회한다. 대상 또는 확정 여부가 모호하면 변경하지 않고 근거와 확인할 사항을 보고한다. 이번 요청이 이해·대조·검토만이면 상태를 변경하지 않는다. 메일 답장·자료 제출·일정 변경은 별도 요청 범위에 따른다.

신고 목록의 수입/수출 열을 확인하고 상태 메뉴에서 진행을 선택한다. 같은 이름이 다른 보호자명에 포함될 수 있으므로 보호자와 동물을 함께 식별한다. 화면 저장이 잠시 지연될 수 있으므로 선택 직후 이전 값이 보인다고 반복 클릭하지 말고, 해당 행의 최종 상태가 진행인지 확인한다. 결과 보고에는 신청번호와 변경한 상태를 함께 적는다.

## 매일 이메일 확인 및 예외 보고

- 현재 정기 작업은 한국 시간 매일 오후 1시에 시작한다. 이전 확인 이후의 일본 검역소·관련 NACCS 메일을 모두 확인한다. 통상 하루 1~3개여도 개수로 제한하지 않는다. 검색 기간을 조금 겹치고 메시지 ID로 중복 제거하며, 결과가 많으면 페이지를 이어 확인한다. 미검토 메일을 건너뛰어 확인 시점을 앞당기지 않는다.
- 발신 답장과 후속 회신까지 확인해 이미 보낸 자료를 다시 미발송으로 보고하지 않는다. 보완자료 발송 완료와 검역소 승인·예약 확정은 구분한다. 수입 승인 메일의 EXPORT 항목에도 수출 예약 확정이 있을 수 있으므로 본문 전체를 읽는다.
- 당분간 자동화는 조회·할 일 보고가 기본이다. 예외로, 명확히 확정된 수출 예약 일시가 펫무브워크와 일치하면 위 기준대로 완료 처리한다. 이메일 발송·자료 업로드·예약 일시 변경·새 신고 제출은 사용자 지시 없이 자동 실행하지 않는다. 발송 자동화는 사용자가 테스트 후 별도로 허용해야 한다. 수입허가서 다운로드·첨부가 필요하면 할 일로 보고하고, NACCS 로그인 CAPTCHA는 해당 시점에 사용자 승인을 받는다.
- **설명된 절차로 처리할 수 없거나 판단이 애매한 새 이메일은 반드시 사용자에게 보고한다.** 동물/보호자, 검역소·메일 시각, 현재 요구사항, 처리할 수 없는 이유, 필요한 자료·사용자 판단·기한을 정리한다. 제목·본문의 대상 불일치, 증빙 누락, 새로운 요청, 예약 충돌을 임의로 해석해 답장·제출·완료 처리하지 않는다.
- Form AC 초안에 문제가 없다는 회신과 최종본 재송부 요청을 구분한다. 사용자가 고객의 검역소 검역 후 카카오톡 사진을 받아 전달한다고 설명한 건은 고객 자료 대기로 기록하며, 사진이 오기 전 즉시 재송부할 일로 보고하지 않는다. 실제 받은 사진의 대상·서류 내용을 확인한 뒤 사용자 지시 범위에서 전달한다.
- 확인 이력과 미완료 상태는 Git에서 제외된 로컬 업무 기록에 남긴다. 처리 필요, 고객 자료 대기, 검역소 회신 대기를 구분한다. 새 조치·예외·승인·예약 확정·오류 등 의미 있는 변화는 알리고, 변화 없는 대기는 중복 알림하지 않는다. 자동 처리 불가능한 새 요청을 단순 대기로 분류해 알림을 생략하지 않는다.
- 업무 PC와 노트북의 정기·수동 점검은 [기기별 점검 인계](../../../docs/laptop-daily-check-handoff.md)의 Google Drive 비공개 이력을 공통 원본으로 사용한다. 시작 전에 최신 이력을 읽고, 종료 시 다른 기기의 갱신을 대조·병합해 동일 원격 파일 ID로 저장한 뒤 재조회한다. 실제 고객 이력·메일 ID·비밀키는 Git에 넣지 않는다. 연결 실패나 충돌 시 동기화 완료로 간주하지 않고 로컬 결과를 보존해 보고한다.

고객 케이스의 개인정보나 과거 신청번호를 스킬에 고정하지 않는다.
