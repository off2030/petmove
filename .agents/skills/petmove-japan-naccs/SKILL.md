# 일본 신고·검역소 업무

[실무 운영 기준](../../../docs/work-management/operations.md)의 대상·권한·필드 해석·중단 인계를 적용한다. 정기 전체 점검은 [정기 점검 스킬](../petmove-daily-review/SKILL.md)로 시작한다. 데이터·PDF 생성은 직접 도구, NACCS와 이메일 작성·첨부·발송·사용자 검토는 로그인된 **Chrome**을 사용한다.

## 작업 선택

| 작업 | 읽을 절차 |
| --- | --- |
| 일본 입국 사전신고·수입검사 | [수입](references/import.md) |
| 귀국편 일본 출국·수출검역 | [수출](references/export.md) |
| 기존 신고 수정·브라우저 오류 | [수정·복구](references/operations.md) |
| 기관 메일·수입 승인·예약 확정·Form AC | [메일·서류](references/mail.md) |

특정 여행 신고 제출 지시가 있고 귀국편이 등록된 왕복이면 명시적인 제한이 없는 한 수입 Notification·Apply 후 귀국 수출 신청까지 이어간다. 귀국편/희망 검역일시가 비거나 모순되면 그 항목만 확인한다. 자료를 지어내지 않는다. 정기 점검만으로 새 신고의 포괄 제출 권한은 생기지 않지만, 이전에 개별 지시받고 중단한 신청은 재개 대상이다.

## 자료와 입력 관례

- 실제 조직·케이스·여행·보호자·동물·칩번호를 현재 Work와 기관 기존 신청으로 대조한다. 같은 보호자의 동반 동물과 다른 차수 여행을 구분한다. 분리 보호자명·by_dest·회차·조직 기본값은 현재 화면/PDF와 동일하게 해석한다.
- 생년월일·성별·품종·모색·체중·칩 삽입일·접종/유효기간·항체 채혈일/기관/결과·왕복편·한국/일본 주소·보호자 연락처를 확인한다. 첨부 원본은 이름/칩번호로 대조하고 이동가방 전체 사진은 잘 나온 한 장을 사용한다.
- 신청자 `JINWON LEE AND {OWNER}`, 이메일 `lvmcfile@gmail.com`; 보호자 현지 연락은 보호자 전화·이메일. 대문자 입력 형식을 따른다.
- 실측이 없으면 사용자 관례에 따라 품종·실제 체중에서 길이·높이를 5cm 단위로 추정한다. 칩 위치 NECK, 제조사 OTHER, 규격 ISO는 사용자 기본값이며 실제 증빙과 충돌하면 확인한다.
- 접종은 선택한 필요 기록을 최신 먼저, INACTIVATED, `제품/제조사` 형식과 실제 면역기간으로 입력한다. 다른 제품을 본원 기본값으로 바꾸지 않는다. 항체도 최신 먼저, 결과 0.5 이상은 해당 범주를 선택한다. APQA 서울 KR01은 결과지 기관·주소가 일치할 때만 사용하고 조회된 기관명·주소를 확인한다.
- 이 관례를 법적 요건 전체로 설명하지 않는다. 법적 요건 판단은 당시 공식 AQS 근거로 확인한다.

## 제출·Work 반영·인계

1. 같은 여행의 유효한 기존 신청과 실제 발신을 확인해 중복을 막는다. 위임 작업은 공통 지침대로 비공개 delegatedTasks에 기록하고 실행한다.
2. 실제 Application Completed와 번호를 확인한다. Notification 등록만으로 수입검사 Apply까지 끝났다고 하지 않는다. 왕복이면 두 슬롯의 신청번호를 확인한다.
3. 신청 완료 뒤 해당 Work 수입/수출을 진행으로 반영하고 저장값을 직접 재조회한다. 기존 완료를 낮추지 않는다. 신청 접수는 승인·예약 확정이 아니다.
4. 승인·예약 확정의 완료 판정과 승인서 후속 작업은 메일 절차로 수행한다. 희망 일시를 확정으로 표현하지 않는다.
5. 일부만 끝났으면 실행분·미완료 단계·이유·다음 행동을 보고한다. NACCS 메뉴와 작성 중 탭은 현재 도구 handoff로 보존한다. 중단 지시와 경고는 정기 보고 검증에서 생략할 수 없다.
