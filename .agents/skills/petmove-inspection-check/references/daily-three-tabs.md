# 매일 검사·신고·서류 세 탭 점검

2026-10-30 사용자 지시: 기존 매일 점검에서 **검사·신고·서류 세 탭을 모두** 확인한다. 검사 지연이나 일본 메일 확인만 마치고 세 탭 전체 점검을 완료했다고 보고하지 않는다. 업무 PC·노트북의 기존 요일 분담과 오후 1시 일정은 유지한다.

## 공통 조회

- 실제 로잔동물의료센터 조직 ID를 조회해 고정하고, 비삭제 케이스를 안정적인 ID 정렬·명시적 페이지 범위로 끝까지 읽어 정확 건수와 대조한다. 다른 조직은 제외한다.
- 현재 `apps/admin/components/todos/todos-app.tsx`의 탭 포함 조건과 행 구성, 실제 조직의 `organization_settings.inspection_config`·`import_report_countries` 및 설정 정규화 로직을 적용한다. 케이스 수와 각 탭 행 수를 구분한다.
- 활성 여행지 선택·`by_dest`·분리 보호자명·회차별 상태 등 [실무 지침](../../../../docs/work-management/operations.md)의 실제 화면/PDF 필드 기준을 따른다. 원시 컬럼 한 개나 과거 조회 사본으로 현재 상태를 판정하지 않는다.
- 조회와 대조는 읽기 전용이다. 이 점검 범위가 신청 제출·일정 수정·일반 상태 변경 권한을 확대하지 않는다. 이미 위임된 예외만 해당 스킬의 조건대로 실행·재조회한다.

## 검사

- `buildInspectionRows`와 `apps/admin/lib/inspection-status.ts`로 항체검사 재검사 회차·여행지별 전염병검사를 빠짐없이 확인한다. 실제 설정과 동일한 검사기관 기본값을 사용한다.
- 대기·검사 중을 우선 확인한다. 5일 이상 waiting만 대기 지연으로 하루 한 번 보고하고, 미래일·testing·날짜 누락은 지연으로 단정하지 않는다.
- 결과값·결과지가 등록됐지만 아직 검사로 표시되는 회차는 고객 안내 완료와 구분해 보고한다. 결과 안내·신청 확인만으로 공식 상태를 바꾸지 않는다. 검사비 결제 후 진행 전환은 사용자가 직접 한다는 기존 지시를 유지한다.
- 사용자 지정 제외는 공유 이력의 케이스 ID·정보 지문으로 재검증한다. 임의로 다른 케이스까지 제외하지 않는다.

## 신고

- `apps/admin/lib/import-report-selection.ts`의 자동/수동 포함·숨김·활성 여행지 선택과 `apps/admin/lib/report-status.ts`의 수입/수출 상태·완료 판정을 그대로 적용한다.
- 미완료의 대상 여행·신고기한·수입/수출 중 남은 쪽·기관 회신 대기 이유를 확인한다. 진행 건을 미신청으로 보고하거나 등록 통지를 승인으로 해석하지 않는다.
- **2026-10-31 사용자 지시: 신고 탭의 수입/수출 중 하나라도 대기·진행인 여행은 해결될 때까지 매 점검에서 계속 추적한다.** 새 메일이 없는 날도 현재 저장값으로 대상 목록을 다시 구성하고, 이전 미완료 할 일과 대조한다. 한쪽이 완료여도 다른 쪽이 남으면 추적을 끝내지 않는다.
- 대기는 실제 미제출인지, 자료·일정·사용자 판단·로그인 등 무엇이 막는지 확인한다. 진행은 실제 제출번호, 최신 기관 회신과 발신 답장, 승인서 발급/첨부, 예약 확정 여부를 대조한다. 승인 메일은 왔지만 승인서를 받을 수 없거나 Work에 미반영인 건도 남은 할 일로 유지하며 다음 점검에서 재확인한다. 기관에 접속하지 못하면 확인 시각과 제약을 남기고 확인 완료로 추정하지 않는다.
- **명확한 수입 승인 회신이 있으면 수입 완료를 반영·재조회한다.** 승인서 미발급/다운로드·첨부 장애는 별도 후속 할 일이며, 이 파일 작업만을 이유로 수입을 진행에 두지 않는다. 수입 완료 건도 남은 승인서 보관 작업과 미완료 수출 슬롯은 계속 확인한다. 구체적인 근거 판정과 상태 반영은 일본 스킬을 따른다.
- 대상 여행별로 다음 행동·기한·대기 사유·마지막 확인 근거·재개 위치를 같은 비공개 공유 이력에 이어 적는다. 실제 새 회신·자료 도착·발급 가능 여부·기한 임박/경과·오류/불일치·필요한 사용자 판단을 발견하면 보고하고 기존 위임 안에서 처리한다. 변화 없는 대기도 다시 확인하지만 같은 알림을 반복하지 않는다. 상태 사본만으로 별도 완료 판정을 만들거나 새 신고·이메일 발송 권한으로 확대하지 않는다.
- **한국 출국일이 지났어도 귀국일이 남은 왕복 여행의 일본 수출검역은 확인 대상이다.** 출국일이 오늘 이후인 행만 추려 수출 대기를 누락하지 않는다. 실제 귀국일·희망 검역일·예약 회신을 함께 대조한다.
- 현재 숨김 행은 화면 목록과 구분한다. 화면에 보이지 않는 건을 확인했다고 추정하거나 점검만으로 숨김을 해제하지 않는다.
- 정기 점검은 새 신고의 포괄 제출 허가가 아니다. 제출 지시가 있는 케이스는 일본 스킬 등 해당 기관 절차로 처리한다. 확정 예약 일치·수입 승인서 처리·Form AC의 기존 위임은 유지한다.

## 서류

- 실제 포함 조건은 어느 여행지든 출국일 또는 내원일이 있는 케이스다. `export_doc_active_dest` 선택과 `exportDocDeparture`·`exportDocVetVisit`·`exportDocStatus`·`exportDocMemo`의 동일한 우선순위를 사용한다.
- 현재·예정 여행의 내원일, 내원가능일, 준비상태, 메모와 내원일 유효 구간을 확인한다. 우선순위는 가까운 내원/출국과 미완료다. 예정 내원을 이미 실시한 검진으로 표현하지 않는다.
- 내원일이 오늘부터 7일 이내인 준비 대기, 내원일 경과 뒤 남은 준비, 날짜 구간 불일치를 확인한다. 출국일이 없는 과거 내원 기록은 당장 출국하는 신규 업무로 추정하지 말고 오래된 정리 필요 기록과 구분한다.
- 탭의 준비상태·날짜를 확인한 것과 증명서 PDF 원본의 내용 검토는 구분한다. 실제 PDF를 열어 대조하지 않았으면 서류 원본까지 검토했다고 보고하지 않는다. 초안 출력·Form AC 발송만으로 서류 준비 완료를 찍지 않는다.

## 보고·인계

- 세 탭 각각의 실제 확인 시각·조직·전체 페이지/정확 건수·검토 범위를 비공개 공유 이력에 남긴다. 확인하지 못한 탭과 이유가 있으면 부분 점검으로 보고한다.
- 새 할 일·기한 임박·누락·불일치·처리 결과만 알리고, 변화 없는 대기는 중복 알림하지 않는다. 5일 이상 검사 대기의 기존 하루 한 번 보고 예외는 유지한다.
- 보조 이력에는 남은 행동·자료/회신 대기 이유·기한·확인 근거·재개 위치만 관리한다. 공식 검사/신고/서류 상태의 별도 운영 원본을 만들지 않는다. 실제 값을 인용하면 조회 시점의 근거 사본임을 분명히 한다.
- [기기 인계 지침](../../../../docs/laptop-daily-check-handoff.md)에 따라 원격 최신본을 병합·동일 파일 갱신·재조회한다. 다른 기기의 실제 예약까지 바뀌었다고 추정하지 않는다.
