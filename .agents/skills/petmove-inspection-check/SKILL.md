# 검사기관 신청 대조·신청

[실무 운영 기준](../../../docs/work-management/operations.md)의 조직·필드 해석·권한·중단 인계를 적용한다. 정기 세 탭 전체 점검은 [정기 점검 스킬](../petmove-daily-review/SKILL.md)과 [세 탭 검증 절차](references/daily-three-tabs.md)를 사용한다.

## 요청과 자료

- 이름이 주어지면 저장소 루트에서 `node scripts/inspection-lookup.mjs <동물이름> [동물이름...]`으로 읽기 전용 조회한다. 요약은 원본 전체가 아니므로 필요한 분리 이름·by_dest·회차·백신 직접값/조직 기본값을 현재 소비 규칙으로 확인한다. 조회 스크립트에 쓰기 기능을 넣지 않는다.
- 보호자·동물·칩번호·채혈일·기관으로 케이스와 회차를 확정한다. 여러 후보는 자료로 구분하고 필요한 최소 확인만 요청한다. 날짜 형식/대소문자 차이와 실제 불일치를 구분한다.
- 기관 신청 확인만으로 새 신청·수정·결제·Work 상태 변경 권한은 생기지 않는다. 새 신청은 명시적 대상 지시를 따른다. 결제와 그 이후 검사 진행 전환은 사용자 담당이다. 결과지 원본이 현재 회차와 확실히 일치하는 경우는 [실무 운영 기준의 검사 결과 완료 위임](../../../docs/work-management/operations.md#권한)에 따라 해당 회차를 완료·재조회한다. 기존 완료를 낮추거나 다른 회차를 일괄 변경하지 않는다.
- 기관 대조에 무관한 Gmail/Notion을 탐색하지 않는다. 정기 일본 메일 검토는 별도 업무다. KSVDL 결제는 [결제 스킬](../petmove-ksvdl-payment/SKILL.md)을 사용한다.

## 실행

1. 기관 접속 전 [Chrome 연결](references/chrome-access.md)을 읽고 사용자 펫무브 프로필을 사용한다.
2. 현재 조직 검사 설정으로 기관을 판정하고 [기관별 참조](references/providers.md)를 적용한다. APQA 세부 기관 구분을 사용자에게 대신 맡기지 않는다. 조회 요약의 고정 기본값과 현재 설정이 다르면 현재 설정·화면 기준으로 재확인한다.
3. 확인 요청은 기존 기관 내역·신청 PDF와 Work를 비교한다. 일치/불일치/확인 불가, 항목별 양쪽 값·확인 제한을 보고한다.
4. 신청 요청은 [신청 절차](references/application.md)를 읽고 중복 확인 → 필수 항목 대조 → 지정 범위 작성/저장/제출 → 기관 목록 재열기·저장번호·전체 입력·사진·결제 여부 확인까지 수행한다.
5. 초안/클릭/입력 화면을 신청 완료로 보고하지 않는다. 오류는 정상 복구 후 미완료 단계·자료·기한·재개 위치를 기록한다. 기존 위임이 남으면 다음 점검의 중단 지시 대상이다.

직접 조회 경로가 실패하면 사유를 알리고 `https://work.petmove.co.kr/cases?view=inspection`에서 필요한 범위만 확인한다. 개인정보·고객 신청번호를 스킬에 고정하지 않는다. 과거 완료 건 전체를 일반 보고하지 않으며 사용자 지정 제외는 케이스 ID와 현재 정보 지문이 일치할 때만 유지한다.
