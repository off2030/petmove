# 필리핀 수입허가증

[업무 구조](../../../docs/work-management/README.md), [공통 권한](../../../docs/work-management/operations.md#필리핀-담당-상시-업무), [기기·공유 이력](../../../docs/laptop-daily-check-handoff.md)을 적용한다. 로잔동물의료센터의 필리핀 **수입 SPSIC** 담당이다. 다른 국가·수출 신고·일반 서류 준비로 상시 권한을 넓히지 않는다.

## 실행 순서

1. Work DB를 읽기 전용으로 직접 조회하고 현재 신고탭 선택 함수로 여행 차수별 대기·진행·완료를 확인한다. 화면 활성 여행 하나만 조회하지 않는다. 원본 첨부·공유 이력·기관 기존 신청을 대조한다. 조회 실패 때는 사유를 알리고 필요한 범위만 브라우저로 확인한다.
2. [신청 요건](references/eligibility.md)의 모든 항목을 실제 근거로 확인한다. 정보·서류·시기·현재 규정 중 하나라도 누락·모순·미확인이면 제출하지 않고 해당 건의 다음 행동·재검토일·기한을 보고한다. Work 값과 원본이 다르면 임의로 고치거나 한쪽을 조용히 채택하지 않는다.
3. 케이스 잠금을 얻고 현재 Work·기관 내역을 다시 읽는다. 기존 신청이 있으면 같은 신청을 이어간다. 준비 완료 건만 [InterCommerce 절차](references/intercommerce.md)로 작성·첨부·검토·제출한다. 현재 도구가 해당 시점의 CAPTCHA·확약 등 사용자 확인을 요구하면 재개 위치를 보존하고 요청한다. 이미 받은 유효한 권한을 이유 없이 다시 묻지 않는다.
4. 실제 접수 번호·UNDER REVIEW를 확인하면 해당 여행 수입 항목만 Work 진행으로 반영·직접 재조회한다. 신청번호는 비공개 실행 근거에 보관하며 허가번호 칸에 넣지 않는다. 업로드·Save 성공만으로 진행으로 바꾸지 않는다.
5. **신청된 모든 미종결 건의 승인 여부를 매일 확인·보고**한다. 출국일이 지나도 미승인·보완·Work 반영 실패 건은 유지한다. Work 완료인 현재/미래 여행도 출국일까지 허가 유효성을 확인한다. 승인 시 원본 허가증·대상·칩·여행·유효기간을 대조하고 해당 Work 여행에 보관한 뒤 수입 완료를 저장·재조회한다. 승인 통지와 원본 확보·보관 실패는 구분해 보고한다.
6. 잠금을 해제하고 공유 원본의 기존 필드를 보존 병합·재조회한다. 비공개 근거에는 조직·케이스·여행 토큰·신청번호·확인 시각·기관 화면/원본·오늘 처리·남은 일·기한을 연결한다. 공식 상태는 Work 저장값만 사용한다.

## 매일 10:30

업무 PC에서 **매일 10:30 Asia/Seoul, 목·일 포함** 실행한다. [정기 점검](../petmove-daily-review/SKILL.md)의 `--scope philippines`로 시작·종료 전체 대상 합집합과 필수 소스 `philippineRequirements`, `philippineApplications`를 검증한다. 기존 세 담당 예약의 요일은 그대로다.

- 대기: 정보·서류·신고 시기 전체 검토 → 완비 건 신청 → 실제 접수·Work 진행 재조회. 이른 건은 적정 신청일, 늦은 건은 처리기간 위험을 구체적으로 남긴다.
- 신청 건: 기관 로그인 후 신청번호별 실제 현재 상태·보완 본문·허가 원본을 확인한다. 이메일만 있거나 접속이 안 되면 승인 여부 미확인으로 보고한다. UNDER REVIEW를 승인으로 쓰지 않는다.
- 승인: 원본 보관·완료 반영을 확인한다. 추가 서류·새 확약·일정 변경 등은 현재 위임 범위를 확인한다. 보완자료가 완비되고 사실 변경이 없는 기존 신청의 첨부 보완은 같은 절차로 진행하며, 사실 정정·취소·새 비용은 별도 권한을 확인한다.

보고는 `대상(보호자)·여행 | Work 상태 | 신청번호·기관 상태·오늘 확인 시각 | 오늘 처리 | 남은 일·기한`으로 같은 동물·여행을 한 행에 묶는다. 매일 신청 건의 승인 여부는 변화가 없어도 생략하지 않는다. 자료 불일치·보완·반려·접속 장애·사용자 확인 필요는 별도 설명한다. 대상이 없으면 조회 범위와 0건을 알린다. `render → 공유 원본 저장·재조회 → complete`를 통과해야 담당 점검 완료다.

## 보관 경계

계정·비밀번호·여권·주소·고객 첨부·실제 신청번호를 이 스킬·예약 프롬프트·Git에 넣지 않는다. [InterCommerce 계정 절차](references/intercommerce.md)의 보호자 이메일·TIN 여권번호 지시와 지정 비밀번호 로컬 암호화 저장소를 먼저 사용하며 이미 제공된 값을 반복해서 묻지 않는다. 실제 원본과 실행 사본은 Work/비공개 공유 원본/추적 제외 작업 폴더에 둔다. 고객·기관 이메일이나 카카오 발송은 이 스킬의 자동 권한에 포함하지 않는다.
