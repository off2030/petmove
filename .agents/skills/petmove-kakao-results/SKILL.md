# 검사결과 고객 안내

[실무 운영 기준](../../../docs/work-management/operations.md), [공유 이력](../../../docs/laptop-daily-check-handoff.md)을 적용한다. 수신 파일 보관/정보 입력은 [자료 스킬](../petmove-kakao-documents/SKILL.md), 기관 신청 대조는 [검사 스킬](../petmove-inspection-check/SKILL.md)이다.

## 권한과 대상

**고객 자동 발송은 금지한다.** 자동 점검 범위는 원본 결과 확인·연락 할 일 관리·사용자 보고다. 기존 방이 명확해도 전송하지 않는다. 특정 고객·문구·결과지 발송 지시가 확인되면 같은 승인을 반복 요구하지 않고 실행한다. 단순 검토·방 찾기·문구 작성 요청에는 파일 선택도 하지 않는다. 카카오 UI는 파일 선택만으로 즉시 전송할 수 있다.

로잔 조직의 현재 케이스·여행·검사 회차를 직접 조회한다. 카카오 채널 이름을 DB 조직으로 오해하지 않는다. 검사 결과 확인에 따른 회차 완료는 공통 운영 기준의 위임을 적용한다. 고객 안내 여부로 검사/신고 상태·상담 상태·중요표시를 변경하지 않는다.

## 연락 할 일과 결과 확인

1. 정기 실행은 [정기 점검 스킬](../petmove-daily-review/SKILL.md)로 시작한다. 실시간 등록 이벤트를 감지하는 기능으로 표현하지 않는다.
2. `node scripts/inspection-result-notice-snapshot.mjs work/naver-inquiries/result-notice-current.private.json`의 전체 첨부와 공유 kakaoResultNoticeQueue의 seenAttachmentFingerprints·미발송·실제 발송을 비교한다. 초기 과거 첨부는 비교 기준이며 기발송이 아니다. 날짜 필터·검사 done만으로 후보를 제외하지 않는다.
3. documents/notes의 같은 파일은 경로로 중복 제거하고 재등록/교체 파일은 식별정보·크기·시각으로 구분한다. 제목·태그·resultCandidate는 단서다. false인 새 파일도 원본과 문맥을 확인한다. 원본 미확인은 확인 할 일로 남기며 단순 seen으로 넘기지 않는다.
4. 원본 보호자·동물/칩·채혈일·검사 종류·기관·결과를 현재 회차와 대조한다. 업로드일·발급일·채혈일을 구분한다. 실제 수치/비교부호를 보존하며 결과 상태와 공식 검사 상태를 혼동하지 않는다.
5. 큐에는 조직·케이스/회차·첨부 식별정보·등록/확인일·남은 행동·기존 채팅방 근거·문구 확인·기보고 시각을 남긴다. 검사/신고의 독립 상태를 만들지 않는다. 사용자가 직접 확인할 건은 그 대기로 두고 자동 검색·발송·반복 요청하지 않는다.
6. 신규 결과/미확인/오류를 동물·보호자, 검사 종류·확인 결과, 등록일, 방 확인 여부, 남은 행동과 함께 보고한다. 정기 검증의 findings에 포함하고 resultNotices 검토 근거를 남긴다. 일반적인 동일 기보고 대기는 공통 중복 기준을 따른다. 전체 목록 요청에는 남은 할 일을 모두 보고한다.

## 지시받은 발송

[원본 대조·채팅방·발송 절차](references/sending.md)와 [Chrome 연결](../petmove-inspection-check/references/chrome-access.md)을 읽는다. 실제 대화·동물·검사/여행으로 기존 방을 확정하고, 발송 직전 최신 대화와 공유 이력에서 사용자 수동 발송까지 중복 확인한다.

실제 재조회한 문구·이미지 수량·발송시각 또는 사용자의 완료 확인으로만 연락 할 일을 해결한다. 일부 성공은 남은 첨부만 이어 보내고 불명확하면 실제 대화부터 재조회한다. 결과 화면 보관 후 공유 최신본 병합·동일 파일 갱신·원본 재조회를 마친다. 충돌·실패는 중단 지시와 함께 인계한다.
