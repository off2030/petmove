# 검사 결과 확인과 카카오톡 고객 안내

[실무 지침](../../../docs/work-management/operations.md)과 [Chrome 연결 지침](../petmove-inspection-check/references/chrome-access.md)을 따른다. 수신 서류 보관·정보 입력은 [카카오 서류 스킬](../petmove-kakao-documents/SKILL.md), 검사기관 신청 대조는 [검사 스킬](../petmove-inspection-check/SKILL.md)을 사용한다.

## 요청 범위

- **2026-10-23 최종 사용자 지시: 고객에게 자동 발송하지 않는다.** 새 결과지는 확인·안내 할 일 목록 관리·사용자 보고까지 자동 수행한다. 기존 채팅방이 확실해도 발송하지 않는다. 사용자가 발송을 지시하면 대상·실제 문구·첨부를 확인받고 보낸다. 이미 특정 고객·문구·결과지 전송을 확인한 지시는 같은 승인을 반복 요구하지 않고 실행한다. 검토·문구 작성·채팅방 찾기·목록 보고만 요청했으면 전송 버튼이나 파일 선택을 실행하지 않는다.
- 스킬 저장 자체는 전체 고객 일괄 발송·정기 자동 발송 위임이나 예약 변경이 아니다. 반복 발송은 실제 위임된 대상·조건에 한정한다. 중요표시·상담 상태·검사/신고 상태를 이 작업만으로 변경하지 않는다.
- 펫무브워크 조직은 실제 로잔동물의료센터 ID로 고정한다. 카카오 채널명 `펫무브`와 DB의 셀프서비스 조직 `펫무브`는 구분한다. 같은 병원 고객이 펫무브 또는 로잔 채널에서 상담할 수 있으므로 현재 대화·보호자·동물로 확인한다.

## 새 결과지의 안내 할 일 목록과 사용자 보고

- 기존 오후 1시 정기 점검에서 이 목록을 확인한다. 즉시 이벤트 감지 기능이 구현된 것으로 설명하지 않는다. 기존 업무 PC·노트북의 요일 분담은 유지한다. 실제 예약이 수정된 기기와 문서만 인계된 기기를 구분해 보고한다.
- 비공개 공통 Drive 검토 이력의 `kakaoResultNoticeQueue`에 **고객 연락 할 일**을 보관한다. 검사 결과와 공식 검사/신고 상태는 실행 때 펫무브워크에서 다시 읽는다. 이 큐에 독립적인 검사 완료/진행 상태를 만들지 않는다.
- 최초 설정 때 전체 조직 범위를 확인한 첨부 식별목록과 기준시각을 저장한다. 기존 과거 첨부는 초기 비교 기준으로 보존하고 기발송으로 간주하지 않는다. 이미 확인한 미발송 안내는 별도 할 일로 이어받는다. 사용자가 직접 확인하겠다고 한 건은 `사용자 확인 대기`로 두고 자동 검색·발송 및 같은 내용의 반복 요청을 하지 않는다. 스킬에는 실제 고객명을 고정하지 않는다.
- 이후 매 실행마다 전체 페이지를 읽어 현재 첨부를 저장된 식별목록과 비교한다. `documents`와 `notes`의 파일 첨부를 같은 경로 기준으로 중복 제거하며, 신규/교체된 첨부를 파일 ID·경로·크기·업로드 시각 등으로 구분한다. 날짜만 잘라 오래 미실행한 기간의 결과를 누락하거나 검사 상태가 완료라는 이유로 안내 후보를 제외하지 않는다. 첨부 제목·태그는 후보 단서이며 원본 내용으로 검사결과 여부와 대상을 확인한다. 원본을 못 읽었으면 확인 필요 할 일로 남긴다.
- 첨부 비교에는 저장소 루트에서 `node scripts/inspection-result-notice-snapshot.mjs work/naver-inquiries/result-notice-current.private.json`을 사용할 수 있다. 이 도구는 실제 조직 식별·전체 페이지·정확 건수·첨부 중복 제거와 지문을 제공하는 **읽기 전용 조회**이며 검사결과 내용 판정이나 전송을 하지 않는다. `resultCandidate`는 제목/태그의 후보 단서이고 false인 신규 파일도 원본 검사결과일 수 있으므로 문맥으로 확인한다. `kakaoResultNoticeQueue.seenAttachmentFingerprints`는 초기 기준 및 검토한 파일의 지문이다. 신규 파일은 내용을 확인해 일반 첨부로 제외하거나, 확인/안내 할 일에 등록한 뒤에만 지문을 반영한다. 미확인 파일을 단순히 본 것으로 처리해 누락하지 않는다.
- 큐 항목은 조직·케이스/회차·보호자·동물·첨부 식별정보·등록/확인 시각·남은 행동·채팅방 확인 근거/미확정 사유·문구 검토 여부·마지막 사용자 보고시각을 담는다. 실제 검사 결과를 인용하면 조회시각을 붙이고 공식 상태 사본임을 구분한다. 검사명은 광견병 항체/기타 항체/전염병 검사 등을 혼동하지 않는다.
- 새 결과지를 확인하면 사용자에게 **동물/보호자, 검사 종류·확인된 결과, 등록일, 기존 채팅방 확인 여부, 남은 확인과 발송 대기**를 간결히 보고한다. 같은 보호자의 여러 동물은 한 행으로 묶되 첨부와 회차를 보존한다. 새 항목·새 오류·고객 회신 등 의미 있는 변화만 알리고, 변화 없는 대기는 조용히 유지한다. 사용자가 목록을 요청하면 현재 남은 전체 연락 할 일을 보고한다.
- 실제 채팅과 공유 발송 이력에서 보낸 결과임이 확인되거나 사용자가 직접 발송 완료를 알려준 경우에만 그 안내 할 일을 해결된 기록으로 옮긴다. 문구만 발송·첨부 실패 같은 부분 성공은 남은 첨부를 계속 관리한다. 사용자 지시 대기나 채팅방 미확정을 완료로 바꾸지 않는다.
- 이 설정 요청을 과거 결과지 전체 재안내나 즉시 고객 일괄 발송으로 해석하지 않는다. 로컬 작업 사본·원격 저장·병합·재조회는 기기 인계 절차를 따르고 충돌 시 최신 원격을 덮지 않는다.

## 결과지와 회차 대조

1. 구성된 읽기 전용 경로로 현재 케이스·보호자·동물·칩번호·대상 여행·검사 회차·결과값·상태·첨부를 조회한다. 화면/PDF의 실제 우선 필드·폴백을 사용한다. 전체/오늘 결과 조회는 안정적인 정렬로 모든 페이지를 읽고 정확 건수와 대조한다.
2. `data.documents`의 실제 검사결과 첨부와 `stepId`, `uploadedAt`, `path`, `size` 등을 확인한다. 오늘 결과를 요청했다면 한국 날짜 기준 첨부 시각으로 후보를 찾되, **업로드일·기관 발급일·검사일·채혈일은 구분**한다. 다른 서류나 단순 케이스 수정 시각으로 결과 수신을 확정하지 않는다. 보관함에만 있는 결과도 문서 내용으로 확인한다.
3. 해당 첨부 원본을 정상 경로로 내려받아 실제 열림·크기와 내용을 확인한다. 현재 버킷·경로 모델은 앱의 첨부 구현을 먼저 읽는다. 고객 파일은 Git 제외가 확인된 비공개 작업 폴더에만 둔다. 공개 링크를 만들어 전달하지 않는다.
4. 결과지 보호자명·칩번호·채혈일·기관·결과와 해당 회차를 대조한다. 이름이 없는 결과지는 칩번호로 동물을 식별한다. 같은 보호자의 여러 동물도 각각 대조한다. 과거 결과·다른 회차·다른 고객 자료가 섞이면 발송하지 않는다.
5. 원문의 결과 표현을 보존한다. 예를 들어 FAVN `Positive`와 각주 `≥ 0.5 IU/mL`는 광견병 항체검사 기준치 충족이라는 뜻이며 광견병 감염 진단으로 안내하지 않는다. `≥ 0.5`를 임의의 정확한 수치로 바꾸지 않는다. 기준치 미달·판독 불가·저장값 불일치는 합격 문구로 처리하지 않고 근거와 필요한 판단을 보고한다.
6. 결과가 있어도 공식 검사 상태가 `testing`일 수 있다. 결과 수신과 현재 저장 상태를 구분하고 불일치를 보고한다. 결과 안내 권한을 상태 변경 권한으로 확대하지 않는다. 별도 완료 처리 지시가 있으면 해당 회차만 변경·재조회한다.

## 기존 채팅방 식별과 중복 방지

- 사용자 Chrome의 채널 관리자센터에서 기존 방을 찾는다. 보호자명 → 동물명 → 실제 등록된 영문명·표기 차이 → 목적지 등 확인된 단서를 사용한다. 두 채널의 **전체 상담**을 확인해 완료된 상담 누락을 막는다. 이름 검색은 최소 2글자이며 검색 직후 이전 결과가 잠시 남을 수 있으므로 새 검색값과 갱신된 결과를 함께 확인한다.
- 채팅방 이름만으로 확정하지 않는다. 현재 대화의 동물·채혈일·접종/검사 예약·여행 정보 등을 DB·결과지와 대조한다. 비슷한 이름이나 같은 목적지만 일치하는 다른 고객에게 발송하지 않는다. 찾지 못하면 기존 메모·연결된 고객 식별정보 등 정상 조회 경로를 더 확인하고, 그래도 특정할 수 없을 때 필요한 최소 단서를 보고한다. 고객명·전화번호를 공개 검색엔진에 넣지 않는다.
- 기존 방이 `친구아님`으로 표시돼도 입력·전송이 가능한 경우가 실제 확인됐다. 이 표시만으로 채널 친구 추가가 필수라고 단정하지 않는다. 실제 전송 불가·차단 상태는 구분한다. 고객을 임의로 친구그룹에 넣거나 새 채팅 상대를 추정하지 않는다.
- 발송 직전 최신 대화와 기기 간 공유 이력을 읽어 같은 검사·결과지·안내가 이미 발송됐는지 확인한다. 사용자 수동 발송도 포함한다. 이미 보낸 문구는 다시 보내지 않고, 일부만 성공했으면 누락분만 보낸다. 공유 이력은 [기기 인계 지침](../../../docs/laptop-daily-check-handoff.md)에 따라 동시 실행·충돌을 확인한다.

## 안내문·첨부 발송과 재확인

- 결과 사실 중심의 짧은 한국어 안내를 작성한다. 예: `안녕하세요~ [동물]의 광견병 항체검사 결과가 나왔습니다. 기준치인 0.5 IU/mL 이상으로 확인됐습니다.` 같은 보호자의 여러 동물은 모두 대조된 경우 한 문구·한 방으로 묶을 수 있다. 단계별 시험에서는 실제 문구와 대상 방을 먼저 보여준다.
- 여행 대기기간·후속 내원·검역 예약은 해당 여행의 현재 일정과 검증된 국가 지침이 있을 때만 추가한다. 검사결과만으로 전체 입국 준비 완료·예약 확정·방문일을 약속하지 않는다.
- 승인된 문구를 해당 방 입력란에 넣고 `전송`한다. 발송 뒤 텍스트가 대화에 표시되고 입력란이 비었는지 확인한다. 시간 초과 등 결과가 불명확하면 대화부터 재조회하며 반복 클릭하지 않는다.
- 사진/파일 첨부는 현재 DOM에서 실제 첨부 버튼과 파일 선택 기능을 확인한다. `waitForEvent('filechooser')`를 클릭 전에 시작하고 `isMultiple()`을 확인해 대조한 원본 경로만 `setFiles`로 전달한다. **현재 카카오 채팅 UI는 파일 선택만으로 사진 묶음을 즉시 전송할 수 있다.** 미리보기만 할 생각으로 파일을 선택하지 말고 첨부 발송까지 승인된 뒤 실행한다. 선택 후 별도 전송을 요구하는 UI면 대상·수량을 확인하고 완료한다.
- 사진 2장을 선택했으면 대화에 실제 이미지 2장/묶음이 올라왔는지 확인한다. 첨부 중 오류가 나도 이미 보낸 문구를 재발송하지 않는다. 일부 이미지의 성공 여부부터 대조하고 지원되는 정상 복구로 누락분만 처리한다. 더 낮은 해상도로 불필요하게 변환하지 않는다.
- 최종 전송 후 같은 방을 새로고침/재조회해 문구·이미지 수량·발송 시각이 유지되고 실패/재전송 표시가 없는지 확인한다. 미전송 초안·업로드 진행·버튼 클릭만으로 발송 완료라고 하지 않는다. 발송과 고객 열람은 구분한다.
- 결과 화면 스크린샷을 보존하고 보고에 표시한다. 비공개 공유 이력에는 대상 케이스/회차·채팅방·문구·첨부 식별정보/해시·발송 시각·재조회 근거·남은 할 일을 기록한다. 원격 최신본과 병합해 동일 파일을 갱신·재조회하며, 충돌·연결 실패 시 로컬 결과를 보존하고 공유 저장 미완료를 보고한다. 공식 검사/신고 상태는 펫무브워크에서만 읽는다.

## 검증된 동작

2026-10-23 사용자와 단계별 시험에서, 펫무브워크의 동일 보호자 반려견 두 마리 결과지를 원본과 대조한 뒤 기존 카카오 채팅방으로 안내문 1개·결과지 이미지 2장을 발송했다. 복수 파일 선택이 사진 묶음을 즉시 전송했고, 채팅방 새로고침 후 문구·이미지 2장·발송 시각이 유지됨을 확인했다. 실제 고객명·칩번호·채팅방 ID는 스킬에 고정하지 않는다.
